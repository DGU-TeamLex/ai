# 약성분 입력자료 연결 결과

2026-09-14 실행. 모델 재학습이나 서비스 변경 없이, 기존 예측 입력에 약성분 정보를 추가했다.

## 자료와 연결 방법

원본은 Downloads 폴더의 `(한국사회보장정보원)_의료재고예측모델 개발 관련 데이터셋(약성분)_수정.DAT`이다. 3,576,320행을 읽었으며 성분코드가 빈 행은 455,935행이다. 앞선 프로젝트 내부 검색만으로 자료가 없다고 판단할 수 없었으며, 이번에는 실제 파일을 찾아 사용했다.

예측 입력은 `residual-demand-20260914/outputs/residual_demand_v1/prepared.parquet`의 3,730,980행이다. 기관코드와 품목코드가 모두 같고 성분코드가 하나로 결정되는 경우에만 `linked_*` 열에 성분코드·용도구분·약종류구분·약품단위를 추가했다. 숫자처럼 보이는 코드도 문자열로 보존했다. 성분은 일치하지만 단위 등 다른 속성이 충돌하면 해당 속성만 비워 두었다.

기관이 다르고 약품코드만 같은 경우에는 네 속성이 충돌하지 않을 때만 `candidate_*` 열에 후보를 기록했다. 이 후보는 정확히 연결된 값으로 간주하지 않는다. 누락값을 0으로 바꾸거나 기관을 추정하지 않았다.

## 전체 실행 결과

- 기관·품목이 일치하고 성분을 연결한 행: **1,963,256행, 전체의 약 52.62%**. 기관·품목 조합으로는 151,908개다.
- 약품코드만 일치하는 후보: **1,045행**, 79개 조합. 정식 연결 열에는 넣지 않았다.
- 기관·품목은 있으나 연결할 성분이 없는 행: **233,766행**, 26,606개 조합.
- 그 밖의 미연결: **1,532,913행**, 176,992개 조합.
- 원래 입력의 모든 열과 값을 배치 단위로 대조해 동일함을 확인했다. 행 수와 예측 대상 값도 유지했다.

전체에는 약품 외 소모품이 포함되므로 52.62%는 '약품의 성분 연결률'이 아니라 '전체 예측 입력 행의 연결률'이다. 동일 품목의 여러 달이 포함된 행 기준 비율이므로 품목 수 기준 비율과도 다르다.

산출물은 이 작업 폴더의 `outputs/ingredient_link_v1/prepared_with_ingredients.parquet`, `manifest.json`, `status.json`이다. 대용량 입력과 산출물은 Git에 올리지 않는다.

## 사용할 수 있는 범위와 아직 해결하지 못한 부분

같은 성분을 가진 품목을 구분하고, 단위와 약품 분류를 모델 입력 후보로 사용할 수 있게 됐다. 다만 같은 성분이라는 사실만으로 임상적 대체 사용이 가능하거나 실제 대체 사용이 발생했다고 판단할 수는 없다.

원본에는 수집일·적용일이 없다. 따라서 모든 행의 `ingredient_time_verified`를 false로 기록했다. 기관·품목코드가 정확히 일치해도 그 성분 정보가 2018년이나 2025년 당시에도 유효했는지는 별도 문제다. 이 자료로 과거 예측을 검증하면 날짜가 확인되기 전까지 탐색 실험으로 보고해야 한다.

진료·접종 자료는 아직 연결하지 않았다. 익명 기관코드와 공개 기관코드 사이에 검증된 대응표가 없으며, 찾은 통계도 기관별 월별 활동량과 다르다. 다른 병원의 진료인원이나 지역 연간 접종률을 같은 기관의 월별 실적으로 넣지 않았다.

- [부산보훈병원 월별 감면코드별 사비외래진료인원](https://www.data.go.kr/data/15117873/fileData.do): 특정 병원 자료로, 우리 자료의 기관별 진료인원이 아니다.
- [질병관리청 전국 어린이 예방접종률](https://www.data.go.kr/dataset/3075043/fileData.do?lang=ko): 지역별 연간 접종률과 기관별 월별 접종 건수는 서로 다른 값이다.
- [건강보험심사평가원 의약품성분약효정보](https://www.data.go.kr/dataset/15021027/openapi.do): 추가 성분 설명의 확인 후보이며, 이번 실행에서 가져오거나 연결한 자료는 아니다.

## 다음 검증

먼저 성분코드가 기존 메타코드에 이미 반영된 정보를 반복하는지 확인해야 한다. 이후 동일한 학습·검증 기간과 동일한 행을 사용해 기존 입력과 성분 추가 입력을 비교한다. 정확히 연결된 열만 먼저 사용하고 후보 열은 별도 실험으로 분리한다. 성분 자료의 적용 시점과 기관 코드의 일관성을 확인하기 전에는 정식 성능 개선 근거로 쓰지 않는다.

이번 실행은 데이터 연결 작업이다. 모델을 재학습하지 않았으므로 WAPE나 BIAS가 개선됐다는 결과는 없다. 진료·접종 활동량을 대신하는 변수도 만들지 않았다.

## 재현과 검사

```powershell
python scripts/link_ingredient_features.py --prepared <기존입력.parquet> --drug <약성분.DAT> --output <새출력폴더>
python -m unittest discover -s tests -p test_ingredient_link.py
```

출력 폴더가 이미 있으면 실행을 거부해 기존 산출물을 보존한다. 단위 테스트 6개로 코드 보존, 후보 분리, 충돌 처리, 결측 처리, 전체 연결 후 원본 값 유지와 덮어쓰기 방지를 확인했다.

입력 SHA256:

- 기존 입력: `fe36707a5caf608161b8e0f6f5d503fd9f74b8a02463313a70b54cc77e30890c`
- 약성분 원본: `d28c118769fcb0d5f28a13d8c7ff381d80ad468a1623794c8a83f4ce6f1118c4`
