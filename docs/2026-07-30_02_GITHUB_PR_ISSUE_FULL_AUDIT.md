## 1. 결론

열린 PR 6개와 이슈 29개를 모두 확인했다. PR은 모두 GitHub상 `CLEAN`이었지만 테스트와
리뷰 승인이 없었고, PR #53의 연속검토 안전재고 산식은 현재 AI의 정기검토 산식과
충돌했다. 따라서 원격 PR을 닫거나 merge하지 않고, 코드를 로컬 작업 트리에 가져온 뒤
다음 원칙으로 보완했다.

- 분석·로더·데이터 계약 코드는 통합한다.
- import 시 DB나 파일을 실행하지 않게 `main()` 경계를 유지한다.
- 약성분 다중 코드 품목은 대표 성분 하나로 자동 대체군에 넣지 않는다.
- `DATA_MISSING`은 이관·반납입고를 포함한 물리적 가용재고로만 자동 판정한다.
- ai#54가 결정되기 전 DB의 `ss`, `rop`, `target`, `status`, 발주권고는 덮어쓰지 않는다.

## 4. 안전재고 충돌 처리

현재 두 산식 중 하나를 임의 선택하지 않았다.

1. backend 연속검토: `SS = z × sigma × sqrt(L)`, `ROP = mu × L + SS`
2. AI 정기검토: 보호기간 `검토주기 30일 + L`, Module C 위험으로 목표재고 조정

`src/loading/apply_inventory_policy.py`는 현재 `mu`, `sigma`, `mu_forecast`,
`demand_class`, `zero_stock_reason`만 반영한다. 보호 컬럼이 UPDATE문에 다시 들어오면
테스트가 실패한다. 운영 발주 주기와 정본 소유권이 정해진 뒤 하나의 산식으로 재계산해야 한다.
