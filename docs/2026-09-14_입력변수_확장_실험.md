# 입력 변수 확장 실험

## 목적과 변경 범위

기존 사용량 모델은 로컬 저장 파일에서 확인한 51개 변수를 사용한다. 최근 모델 계열 비교의 CatBoost 30개 입력과 다르다. 기존 모델의 변수 목록과 튜닝 매개변수를 고정해 재학습하고, 정보 묶음을 추가했을 때의 개선을 구분한다. 서비스 모델, 원본 데이터, 이전 실험은 변경하지 않는다.

기존 저장 모델과 완전히 동일한 학습 재현은 아니다. 재학습 기준 모델과 확장 모델끼리 동일 조건으로 비교하고, 저장된 기존 예측은 별도 참고 결과로 표시한다. CPU 스레드 2, 히스토그램 메모리 64MB로 제한한다. 나머지 나무 매개변수는 로컬 사용량 모델에서 확인한 값이다. 최대 1,999회, 검증 MAE가 100회 개선되지 않으면 학습을 마친다. 각 후보에 같은 규칙을 적용한다.

## 실험 후보

- baseline51: 기존 51개 입력으로 재학습.
- behavior: 마지막 양의 사용 이후 경과 개월, 연속 0 개월, 최근 6개월 중 사용 발생 횟수·발생 월 평균, 최근 3개월과 이전 3개월 평균 차이, 직전 월 대비 사용·재고·입고 차이, 재고/최근 평균 사용량.
- calendar: 예측 대상 월의 일수, 평일 수, 주말 수. 공휴일을 제외한 진료일 수로 표현하지 않는다.
- peer: 같은 시점·품목 계열·규격·단위에 속한 다른 기록의 평균 사용량, 사용 발생 비율, 관측 수. 자기 기록은 제외한다. 단위 변환이나 대체 가능성을 보장하지 않는다.
- behavior_calendar: 사용 패턴과 달력 동시 추가.
- all: 세 정보 묶음 모두 추가.

모든 추가 후보는 baseline51을 포함한다. 정보 묶음별 단독 추가와 누적 추가를 비교한다. 원자재·뉴스는 이번 수요 예측 실험에서 추가하지 않는다.

## 시점 및 누수 방지

`lag_1`은 예측 직전 달, 즉 행의 `year_month`에서 이미 관측한 사용량이다. 미래 정답 `target_usage`는 특성 계산에 사용하지 않는다. 달력은 `forecast_month` 기준이다. 기록이 끊긴 월이나 음수·누락 사용량을 0으로 해석하지 않고 패턴 계산 구간을 끊는다. 사용 이력이 없는 경우의 경과 기간은 결측으로 두고 별도 표지를 추가한다.

동종 품목 정보는 예측 시점에 전체 기관의 해당 월 자료가 확보된다는 전제다. 기관별 데이터 도착 시점은 현재 자료에서 확인하지 못했다. 따라서 이 후보는 동시 월마감 자료 기반 연구 결과로 해석한다. 실제 사용을 위해서는 도착 시각 검증 또는 한 달 더 늦춘 입력이 필요하다.

범주 목록과 숫자 결측 대체값은 각 학습 구간에서만 구한다. 새로운 범주는 미지 범주로 처리한다. 숫자 특성 전체를 일괄 표준화하지 않는다. 단위와 규격 구분 없이 사용량을 합산하지 않는다.

## 평가 방법

승인된 2018~2019년 자료는 가중치 1로 포함한다. 현재 자료는 2024년부터 각 학습 마감 시점까지 사용한다.

- 앞선 검증: 정답 월 2025년 4월까지 학습, 5~6월 검증.
- 최근 검증: 정답 월 2025년 7월까지 학습, 8~9월 검증.
- 선택: 두 검증 구간 절대오차 합을 실제 사용량 합으로 나눈 WAPE 최소 후보. 동률이면 먼저 정의한 단순 후보.
- 평가: 후보 선택 파일을 먼저 기록한 뒤, 최근 구간에서 학습한 기준 모델과 선택 후보만 2025년 10~12월 전체 평가. 이전 비교 자료와 키·정답 일치를 검사한다.

같은 자료의 WAPE는 `100 × 절대오차 합 / 실제량 합`이다. 월별 WAPE의 단순 평균으로 선택하지 않는다. BIAS는 `100 × (예측합 - 실제합) / 실제합`으로 별도 보고한다. 평가 월은 이미 여러 번 사용했으므로 독립 검증이 아니다. 검증 선택 자체도 반복 탐색의 영향을 받을 수 있다. 개선폭을 보장하지 않는다.

## 실행과 산출물

`scripts/feature_expansion_experiment.py suite --source <원본 프로젝트> --reference <이전 evaluation.parquet> --output <새 출력 폴더>`

전 행을 사용하며 품목 샘플링은 하지 않는다. 각 작업을 별도 프로세스로 순차 실행하고 완료 모델·결과는 보존한다. 준비·학습 작업별 2시간 제한과 시스템 가용 메모리 1.5GiB 중단 기준을 적용한다. 강제 종료와 전원 문제를 완전히 예방하는 장치는 아니다. 실패·중단 시 자동으로 재시도하지 않는다.

출력: `status.json`, `manifest.json`, `feature_quality.json`, 검증별 후보 모델 및 점수, `selection.json`, `test_results.json`, `결과요약.md`. 모델과 기관별 자료는 Git에 올리지 않는다. 로컬 pickle은 신뢰할 수 있는 자체 생성 파일만 연다.
