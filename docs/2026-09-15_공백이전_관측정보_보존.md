# 관측 공백 이전 정보 보존

## 가설

이전 점검에서 기록 이력이 6개월 미만인 검증 행 중 176,585개에 이전 구간의 관측이 있었다. 기존 코드는 결측 월에서 연속 구간을 나누므로 최근 지연값·이동평균이 새로 시작한다. 이것은 결측을 실제 0으로 오인하지 않도록 하는 규칙이며 삭제할 오류가 아니다. 현재 구간을 유지하면서 직전 구간의 정보를 별도 제공하는 방법을 준비한다.

## 처리

- 같은 기관·부서·품목 안에서만 비교한다.
- 품목 정의와 단위가 모두 같고 알려져 있어야 한다. 불명확한 분류·단위는 연결하지 않는다.
- 바로 직전 구간만 사용한다. 중간에 단위가 바뀌었다가 돌아와도 다른 구간을 건너뛰어 연결하지 않는다.
- 이전 구간의 마지막 관측량·평균·관측 수와 현재 월까지 경과한 개월 수를 별도 열로 만든다.
- 이전 마지막 관측이 현재보다 2~12개월 전인 경우에만 사용한다. 이 상한은 사전 설정한 탐색 조건이며 최적값이나 임상 기준이 아니다.
- 없는 달은 0으로 채우지 않는다. 과거 값을 현재 직전 월의 값으로 바꾸지 않는다. 원래 입력과 정답을 보존한다.
- 전체 source feature table에서 기록을 읽고 기존 prepared의 모든 행에 왼쪽 연결한다. 미래의 사용량을 바꾸어도 이전 시점에 생성되는 변수가 바뀌지 않음을 테스트한다.

변수 생성 코드와 테스트는 scripts/build_gap_memory.py 및 tests/test_gap_memory.py다. 입력은 기존 outputs/stock_feature_table.parquet와 residual-demand-20260914의 prepared.parquet다. 결과는 이 작업 폴더의 outputs/gap_memory_v1에 보존한다. 기존 산출물은 덮어쓰지 않는다. 모델 학습 전 준비 단계이며 성능 개선을 주장하지 않는다.

## 다음 판정

연결 표본의 규모와 검증 오차 기여를 먼저 확인한다. 제한된 표본만 연결되어 큰 개선의 여지가 작으면 이 변수만으로 대폭 개선을 기대하지 않는다. 새 계열 모델을 평가할 때 원래 74변수와 이 변수 추가 조건을 구별한다. 원래 기준 모델 파일과 서비스는 변경하지 않는다. 성능은 같은 전체 품목·기간의 WAPE와 BIAS로 판단한다.

품목코드와 단위가 같다는 조건만으로 장기간 동일 실물임을 완전히 증명할 수 없다. 변경 이력 없이 과거 값을 확정적으로 되살렸다고 표현하지 않는다. 이번 값은 과거 관측에 대한 보조 정보다.
