# raw_stock 정규화 검증 및 적용 가이드

작성일: 2026-07-12  
검증 대상: `regulazation/물품재고_정규화완료.parquet`  
원본 대상: `raw_stock/*.DAT`

## 1. 결론

현재 Parquet은 **정규화 후보를 만드는 중간 산출물로는 재사용 가능**하지만, WeP-Stock의 재고 사실 테이블이나 최종 품목 마스터로 바로 사용하면 안 된다.

- 사용 가능: 원본 행과 주요 식별 컬럼, 날짜, 기관별 내부 코드와 표준 품목 후보의 연결, 표준 물품명 후보
- 조건부 사용: 공식 코드 기반 `표준품목ID`, `사용량`
- 사용 불가: 정수로 변환된 수량/단가, 검증되지 않은 `NM_*` ID를 최종 품목 ID로 사용하는 방식
- 추가 필요: 품목 유형, 규격/단위 분리, 매핑 신뢰도와 근거, 버전, 검수 상태, 질병 및 원자재 매핑

권장 적용 원칙은 다음과 같다.

```text
현재 Parquet의 표준화 결과
-> legacy alias/mapping candidate로 적재
-> 원본 raw_stock에서 정확한 수치 fact 재생성
-> 품목 마스터 및 별칭 매핑 검수
-> 승인된 canonical_item_id만 예측과 리스크 계산에 사용
```

## 2. 데이터 검증 결과

### 2.1 구조와 보존 상태

| 항목 | 결과 | 판단 |
|---|---:|---|
| 행 수 | 16,265,602 | 원본과 일치 |
| 컬럼 수 | 22 | 원본 컬럼과 정규화 컬럼을 함께 보존 |
| 날짜 수 | 731 | 2024-01-01~2025-12-31 전 기간 보존 |
| 기관 수 | 3,530 | 원본과 일치 |
| 부서 수 | 109 | 원본과 일치 |
| 원본 물품코드 수 | 17,155 | 원본과 일치 |
| 표준품목ID 수 | 107,483 | 원본 코드보다 크게 증가 |
| 표준물품명 수 | 107,065 | 표준 ID와 418개 차이 |

핵심 식별 컬럼과 정규화 컬럼에는 결측치가 없다. `구입단가`는 101,022건만 값이 있고 16,164,580건은 null이며, 이는 원본의 값 존재 범위와 일치한다.

### 2.2 코드 정규화 방식

| 코드 유형 | 행 수 | 비율 | 확인된 방식 |
|---|---:|---:|---|
| 공식코드 | 11,241,523 | 69.11% | 원본 물품코드를 그대로 표준품목ID로 사용 |
| USE코드(규칙기반) | 5,024,079 | 30.89% | 물품명 규칙에 따라 `NM_*` ID 부여 |

공식코드 행은 전부 `물품코드 == 표준품목ID`이고, USE 코드 행은 전부 `NM_*` ID를 사용한다. 같은 기관 안에서는 `기관 + 물품코드`가 하나의 표준 ID에만 연결되므로 기관별 내부 코드 해석에는 일관성이 있다.

다만 전역 기준으로는 다음 문제가 있다.

- 5,883개 원본 물품코드가 둘 이상의 표준 ID에 연결된다. 특히 `USE0000005` 같은 코드는 기관에 따라 수백 가지 물품을 뜻하므로 원본 코드만으로 조인할 수 없다.
- 348개 표준물품명이 둘 이상의 표준 ID에 연결된다. 예를 들어 `혈당스틱`, `BCG`, `임산부철분제`처럼 같은 이름이 여러 공식/NM 코드로 분리되어 있다.
- 10,315개 표준 ID가 둘 이상의 원본 물품명을 포함한다. 공백과 대소문자 통합은 유효하지만, 일부 공식 코드에는 서로 다른 브랜드명이나 용량 표현도 묶여 있어 검수가 필요하다.
- `NM_*` 생성 규칙, 사전 버전, 실행 버전, 신뢰도 및 검수 여부가 파일에 없다. 새 데이터 추가 후 같은 ID가 재현된다는 보장이 없다.

따라서 `물품코드`는 전역 품목 키가 아니며, 현재 `NM_*`도 최종 canonical ID가 아니라 legacy 후보 ID로 다뤄야 한다.

### 2.4 업무 범위 혼입

이 데이터는 의료용품만 포함하지 않는다. 보수적으로 `학용품`, `홍보물`, `기념품`, `복사용지`, `우산`, `볼펜` 등의 키워드만 확인해도 46,142행, 1,525개 표준물품명이 잡힌다.

WeP-Stock에 넣기 전 DB의 `item_groups`를 기준으로 품목을 분류한다. 예측 및 질병/원자재 리스크 연결 대상은 정책으로 허용한 그룹만 사용하고, 나머지는 원본 보존 영역에 남긴다.

### 2.5 DB item_groups 적용 판단

현재 DB 분류는 raw_stock을 운영 단위로 나누는 기준으로 사용할 수 있다.

| item_group_id | 적용 범위 | 기본 예측 처리 |
|---|---|---|
| `MED_ORAL` | 정제, 캡슐, 시럽 등 경구 투여 의약품 | 포함 |
| `MED_INJECT` | 주사제, 바이알, 앰플, 백신 | 포함 |
| `MED_TOPICAL` | 연고, 크림, 패치, 점안제 등 외용 의약품 | 포함 |
| `LAB_REAGENT` | 검사시약, 진단키트, 검사지, 배지 | 포함 |
| `DISINFECT` | 소독제, 살균제, 멸균 관련 소모품 | 포함 |
| `MED_SUPPLY` | 주사기, 거즈, 붕대, 카테터 등 치료재료와 의료소모품 | 포함 |
| `KM_EXTRACT` | 한방엑스제 | 포함 |
| `KM_HERB` | 한방약초 | 포함 |
| `SUPPLEMENT` | 영양제와 건강기능식품 | 포함 |
| `PROMO` | 판촉품, 홍보물, 기념품 | 제외 |
| `FUEL` | 휘발유, 경유, 등유 등 | 포함 |
| `WASTE` | 폐기물 처리용 품목 또는 비용 | 제외 |
| `RENTAL` | 대여 물품 또는 임대성 항목 | 제외 |
| `UNCLASSIFIED` | 근거 부족 또는 현재 체계로 표현할 수 없는 품목 | 미결정 |

이 분류는 제품 자체의 성질과 운영 목적이 함께 들어 있는 **예측 라우팅 분류**다. 예를 들어 같은 밴드 제품도 치료용 재고면 `MED_SUPPLY`, 홍보사업 배포품이면 `PROMO`가 될 수 있다. 따라서 먼저 `institution_id + local_item_code` 단위에 그룹을 부여하고, 승인된 품목 마스터에는 별도의 제품 유형을 유지하는 것이 안전하다.

`UNCLASSIFIED.is_forecastable`의 null은 false로 덮어쓰지 않는다. 이는 아직 판단하지 않았다는 의미로 보존하되, 학습 데이터 선택 조건은 명시적으로 `is_forecastable = true`인 품목만 통과시킨다.

현재 그룹만으로 명확히 표현하기 어려운 일반 사무용품, 청소용품, 위생용품 및 내구성 의료장비는 우선 `UNCLASSIFIED`로 보내고 건수를 집계한다. 비중이 크면 `GENERAL_SUPPLY`, `SANITARY_SUPPLY`, `MED_EQUIPMENT` 같은 그룹을 DB에 추가할지 별도로 결정한다.

## 3. 권장 정규화 구조

### 3.1 Bronze: 원본 보존

`raw_stock/*.DAT`를 읽어 행과 값을 그대로 보존한다.

- 수량: `decimal(20, 6)` 또는 동일 정밀도를 보장하는 타입
- 단가: `decimal(20, 6)`
- 날짜: `date`
- 원본 코드와 이름: 문자열 그대로 보존
- 추가 컬럼: `source_file`, `source_row_number`, `ingested_at`, `schema_version`
- 금지: 정수 변환, 음수 제거, 0 대체, 이름 덮어쓰기

### 3.2 Silver: 운영 단위 정규화

재고 fact와 품목 alias를 분리한다.

`stock_fact` 권장 필드:

```text
stock_date
institution_id
department_code
local_item_code
raw_item_name
opening_qty
closing_qty
inbound_qty
normal_out_qty
return_out_qty
disposal_qty
auto_disposal_qty
adjustment_qty
unit_price
usage_qty
local_item_key
source_file
```

- `local_item_key`: `institution_id + local_item_code`의 안정적인 해시 또는 복합키
- 시계열 집계키: `institution_id + department_code + local_item_key`
- `usage_qty`: 원본 `정상출고량`을 정밀도 손실 없이 복사
- 원본에서 이미 존재하는 음수와 재고 수불식 불일치는 수정하지 않고 품질 플래그로 관리

`item_alias` 권장 필드:

```text
institution_id
local_item_code
raw_item_name
normalized_name
canonical_item_id
legacy_normalization_id
match_method
match_confidence
review_status
effective_from
effective_to
normalization_version
```

현재 Parquet의 `표준품목ID`와 `표준물품명`은 각각 `legacy_normalization_id`와 `normalized_name` 후보로 가져온다.

### 3.3 Gold: 승인된 품목 마스터

`item_master` 권장 필드:

```text
canonical_item_id
canonical_name
item_type
item_group
official_code
official_code_system
manufacturer
form
strength
specification
pack_quantity
unit
is_prediction_target
is_risk_mapping_target
review_status
master_version
```

`canonical_item_id`는 실행 순서에 따라 달라지는 일련번호로 새로 만들지 않는다. 승인된 마스터 레코드에 영구 ID를 부여하고, 이름 변경이나 별칭 추가 시에도 ID를 유지한다.

공식 코드도 코드 체계가 확인된 경우에만 승인한다. 동일 표준명이 여러 공식 코드에 연결되는 것은 포장, 허가, 제조사 또는 사업 코드 차이일 수 있으므로 이름만 같다고 자동 병합하지 않는다.

## 4. 매핑 규칙

### 4.1 이름 전처리와 속성 추출

원본 이름을 보존하면서 별도 컬럼으로 다음 항목을 추출한다.

- 공백, 대소문자, 괄호 및 구두점 표준화
- 제품 기본명
- 제조사/판매사
- 제형
- 함량 및 농도
- 규격과 포장 수량
- 단위
- 무료/유료, 택배용, 사업명 같은 운영 태그

기본명이 같아도 함량, 규격, 단위, 제형이 다르면 자동 병합하지 않는다. 운영 태그만 다른 경우에는 동일 품목 alias 후보로 만들 수 있다.

### 4.2 매칭 우선순위

```text
1. 승인된 기관별 local_item_key alias
2. 검증된 공식 코드 + 코드 체계
3. 정규화 이름 + 제형 + 함량 + 규격 + 단위의 완전 일치
4. 유사도/LLM 기반 후보 생성
5. 사람 검수 후 마스터 반영
```

유사도나 LLM 결과는 최종 ID를 직접 확정하지 않고 후보와 근거만 만든다. 새 매핑에는 반드시 `match_method`, `match_confidence`, `review_status`, `normalization_version`을 남긴다.

### 4.3 item_group 분류 우선순위

한 품목명에 여러 그룹의 키워드가 함께 들어갈 수 있으므로 다음 순서를 적용한다.

```text
1. 사람이 승인한 기관별 품목 override
2. 홍보/판촉, 대여, 유류, 폐기물 같은 운영 목적
3. 검증된 공식 코드와 코드 체계
4. 검사시약, 소독제, 치료재료의 명시적 제품 패턴
5. 제형을 이용한 내복약, 주사제, 외용약 분류
6. 한방엑스제, 한방약초, 영양제 분류
7. 근거가 부족하거나 충돌하면 UNCLASSIFIED
```

예외 규칙이 중요하다. `주사기`, `주사침`, `주사바늘`은 이름에 `주사`가 있어도 `MED_INJECT`가 아니라 `MED_SUPPLY`다. `홍보물품-한방파스`처럼 운영 목적이 명시된 품목은 제품 형태보다 `PROMO`를 우선한다.

자동 분류 결과에는 다음 필드를 남긴다.

```text
item_group_id
classification_method
classification_rule_id
classification_confidence
classification_version
review_status
```

## 5. WeP-Stock 적용 구조

정규화된 품목 ID를 중심으로 두 리스크 경로를 분리한다.

```text
뉴스 키워드 -> 질병 -> canonical_item_id
뉴스/선물가격 -> 원자재 -> canonical_item_id
```

필요 테이블:

- `disease_item_mapping`: 질병-품목 관련도, 필수도, 근거, 검수 상태
- `item_material_mapping`: 품목-원자재 관련도, 사용 부위, 의존도, 근거, 검수 상태
- `material_master`: 원자재명, 동의어, 상위 원자재, 가격 지표 연결
- `item_risk_daily`: 두 경로의 점수와 최종 결합 점수

재고 fact에는 질병이나 원자재 정보를 직접 넣지 않는다. 모든 외부 리스크는 승인된 `canonical_item_id`를 통해 조인한다. 일반 물품과 홍보물은 재고 분석에는 남길 수 있지만 두 리스크 매핑에서는 제외한다.

`is_forecastable`은 수요 예측 포함 여부만 결정한다. 질병 및 원자재 리스크 연결 여부까지 뜻하지 않으므로 다음 채널은 별도 정책으로 둔다.

| 그룹 | 질병 리스크 | 원자재/공급망 리스크 | 원자재 가격 리스크 |
|---|---|---|---|
| 의약품/한방/영양제 | 대상 | 원료 또는 포장재 근거가 있을 때 대상 | 연결 지표가 있을 때 대상 |
| 검사시약/소독/의료소모품 | 대상 | 대상 | 연결 지표가 있을 때 대상 |
| `FUEL` | 제외 | 제외 | 대상 |
| `PROMO`, `WASTE`, `RENTAL` | 제외 | 제외 | 제외 |
| `UNCLASSIFIED` | 승인 전 제외 | 승인 전 제외 | 승인 전 제외 |

## 6. 검증 기준

재정규화 산출물은 아래 조건을 통과해야 한다.

| 검증 항목 | 통과 기준 |
|---|---|
| 행 수 | 원본과 100% 일치 |
| 필수 키 결측 | 0건 |
| 수량/단가 합계 | decimal 기준 원본과 정확히 일치 |
| 사용량 | 원본 정상출고량과 행 단위 일치 |
| 기관별 코드 매핑 | 동일 유효기간에 하나의 canonical ID만 허용 |
| ID 재현성 | 동일 입력/사전/버전에서 동일 ID 보장 |
| 규격 충돌 | 함량, 제형, 단위가 다른 자동 병합 0건 |
| 자동 매칭 품질 | 별도 정답셋에서 precision 98% 이상 |
| 저신뢰/고영향 품목 | 사람 검수 완료 전 운영 제외 |
| 비의료 품목 | item_group_id 분류 후 리스크 매핑 대상에서 제외 |

검수는 사용량 상위 품목과 공급 중단 시 영향이 큰 품목부터 진행한다. 전체 사용량의 80%를 차지하는 품목을 우선 승인한 뒤 나머지 long-tail을 확장하는 방식이 효율적이다.

## 7. 순차 적용 계획

1. 원본 수치 타입을 보존한 Bronze Parquet을 다시 생성한다.
2. 현재 Parquet에서 표준 ID/이름 후보만 `item_alias` 초안으로 추출한다.
3. `institution_id + local_item_code`를 기준으로 기관별 alias를 고정한다.
4. 이름에서 제형, 함량, 규격, 단위, 제조사 및 운영 태그를 분리한다.
5. 품목 유형을 분류하고 WeP-Stock 대상 범위를 확정한다.
6. 공식 코드와 `NM_*` 후보를 샘플 검수하고 canonical item master를 만든다.
7. 사용량 상위 품목부터 질병-품목 및 품목-원자재 매핑을 승인한다.
8. 월별 재고/사용량 집계와 리스크 점수를 `canonical_item_id`로 연결한다.
9. 수치 보존, ID 충돌, 매핑 정밀도 검증을 CI 또는 배치 품질 게이트로 자동화한다.

현재 파일은 2단계의 입력으로는 가치가 있다. 1단계와 최종 마스터 승인을 생략하고 현재 파일만으로 예측 및 리스크 매핑을 시작하는 것은 권장하지 않는다.
