# 품목별 예측 혼합과 메타코드 기반 배분 실험

## 실행 결과

전체 평가 359,335건에 대한 실행을 정상 완료했다. 큰 개선은 없었다. 서비스 모델을 변경할 근거로 삼지 않는다.

8~9월 검증 246,103건의 WAPE는 직접 예측 34.692004%, 품목별 혼합 34.688318%, 품목군 배분 35.438587%, 혼합 후 배분 35.434836%다. 배분 적용 가능 표본은 24,004건이었고 나머지는 원래 예측을 유지했다. 평가 모집단을 축소하지 않았다. 혼합을 선택하고 비중을 고정한 뒤 마지막 평가를 진행했다.

10~12월 WAPE는 직접 예측 34.734137%에서 혼합 34.731940%로 0.002197%p 낮아졌다. BIAS는 -6.632005%에서 -6.636667%로 오히려 조금 나빠졌다. 개선의 실질성이나 통계적 유의성을 주장하지 않는다.

- 10월: WAPE 34.752026% → 34.751027%, BIAS -1.656166% → -1.654935%.
- 11월: WAPE 34.743815% → 34.742875%, BIAS -6.515834% → -6.514634%.
- 12월: WAPE 34.710406% → 34.706076%, BIAS -10.935551% → -10.950414%.

대부분의 집단에서 과거 검증이 선택한 평균 혼합 비중은 0이었다. 전체 기본 비중도 0이다. 즉, 정해진 집단과 후보 안에서는 대부분 기존 모델을 그대로 쓰는 것이 나았다. 최근 3개월 평균으로 배분하는 방식은 검증에서 악화됐으므로 마지막 평가에서 다시 시험해 승자를 바꾸지 않았다.

다음 단계는 별도 총량 예측 모델을 곧바로 늘리기보다, 분류와 단위가 확인된 품목군에서 총량이 실제로 더 안정적인지 먼저 측정하는 것이다. 이번 결과는 단순 비중 배분을 채택하지 않을 근거일 뿐 모든 계층적 예측을 배제할 근거가 아니다. 실제 업무량 자료는 아직 확보하지 않았으며 추가 데이터 효과도 검증되지 않았다.

실행 결과는 로컬 outputs/group_routing_v1의 manifest.json, weights.json, selection.json, test_results.json, predictions.parquet, status.json에 보존했다. 단위검증 4개와 git diff --check를 통과했다.

## 목적과 범위

현재 74개 입력 변수의 직접 사용량 모델을 고정하고, 예측값을 사용하는 방식을 비교한다. 전체 자료에서 예측하며 표본을 축소하지 않는다. 신규 모델 재학습, 기관 데이터 요청, 서비스 변경은 포함하지 않는다. 이전 잔차 학습 실험의 early/recent direct_full 모델과 prepared.parquet를 읽기 전용으로 사용한다. 원본 기관 식별자가 있는 예측 파일은 공개 저장소에 올리지 않는다.

## 비교 방법

1. 직접 예측: 저장된 LightGBM 모델의 음수 예측만 0으로 제한한다.
2. 품목 패턴별 혼합: `최종 예측 = (1-w) × 모델 예측 + w × 최근 3개월 평균`. 과거 평균 사용량(0, 100, 1000, 10000 경계), 변동계수(0.2, 0.8 경계), 과거 기록 6개월 이상 여부로 집단을 정한다. 변동계수는 최근 표준편차/평균이다. 5~6월 절대오차 합을 최소화하는 w를 0, 0.25, 0.5, 0.75, 1 중 선택한다. 표본 500개 미만이거나 실제량 합이 0인 집단은 전체에서 선택한 비중을 쓴다. 임계값은 이번 사전 설정이며 최적이라고 주장하지 않는다.
3. 품목군 배분: 동일 기관·부서·품목군·단위·예측월 안에서 모델 예측 합계를 최근 3개월 평균의 품목별 비중으로 배분한다. `품목 예측 = 묶음의 모델 예측 합계 × 품목의 과거 평균 / 묶음의 과거 평균 합계`. 둘 이상 품목이 있고 분모가 양수일 때만 적용한다. 불명확한 분류·단위는 기존 예측을 유지한다.
4. 혼합 후 배분: 2번 예측을 3번 방식으로 배분한다.

단위 코드 일치는 포장당 수량이나 임상적 대체 가능성을 보증하지 않는다. 품목군 배분은 탐색용이고 권고 발주량으로 쓰지 않는다. 이는 총량 자체를 별도 학습하는 계층 모델이나 MinT 구현이 아니다. 따라서 배분 실패가 모든 계층적 예측의 실패를 의미하지 않는다.

## 평가 순서와 한계

5~6월에서 혼합 비중을 정하고 고정한다. 8~9월 전체 개별 품목 WAPE로 네 방법 중 하나를 선택하고 selection.json을 쓴 뒤 10~12월 실제값을 읽는다. 마지막 구간에서는 직접 예측과 선택 방법만 평가한다. 다른 방법의 마지막 구간 성능을 보고 재선택하지 않는다. 월별 WAPE/BIAS도 보존한다.

기반 모델은 각각 5~6월, 8~9월을 조기종료에 사용한 기존 모델이다. 따라서 이번 절차는 완전히 분리된 중첩 검증이 아니다. 10~12월도 여러 번 분석에 사용되었으므로 독립적인 성능 확증이 아니다. 유망한 결과가 나와도 새로운 기간에서 재검증해야 한다. 집단별 혼합 비중과 분류 기준의 과적합 가능성도 남아 있다.

## 문헌과의 관계

- [FFORMA: Feature-based Forecast Model Averaging](https://robjhyndman.com/publications/fforma/): 시계열 특징에 따라 예측 모델 비중을 달리하는 원리를 참고했다. 이번 구현은 소수의 고정 집단과 비중 후보를 사용하는 단순 비교로, 논문의 FFORMA 직접 재현이 아니다.
- [Forecast reconciliation](https://otexts.com/fpp3/reconciliation.html): 전체와 세부 예측을 함께 고려하는 근거다. 이번 구현은 과거 비중 배분이며 오차 공분산을 사용하는 MinT가 아니다.
- [Inventory Management with Advance Booking Information](https://pubsonline.informs.org/doi/10.1287/msom.2021.0063): 향후 실제 진료·접종 일정 등 사용 활동 정보가 필요한 근거다. 현재 재고 입력에는 해당 활동량이 없다. 외부 자료의 기관 연결과 당시 공개 가능 시점을 확인하기 전 입력에 추가하지 않는다.

## 재현

`python scripts/group_routing_experiment.py --source <residual_demand_v1 경로> --output <새 결과 폴더>`

동일 출력 폴더가 있으면 중단하며 덮어쓰지 않는다. 스레드는 예측 호출에서 2로 제한한다. 학습된 모델 파일은 신뢰하는 로컬 산출물만 사용한다. pickle은 불명확한 외부 파일에 사용하면 안 된다.

`python -m unittest discover -s tests -p test_group_routing.py`

검증 항목은 묶음 총량 보존, 불명확 단위의 원래 예측 유지, 다른 월의 분리, 미래 실제값과 무관한 예측 변환, 혼합 비중의 기본값 처리다.
