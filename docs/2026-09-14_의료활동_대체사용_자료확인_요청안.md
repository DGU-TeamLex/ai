# 의료활동·대체 사용 자료 확인 및 요청안

## 현재 확인 결과

공유 작업트리의 raw_stock, data 및 관련 코드·문서를 읽기 전용으로 점검했다. PC 전체, 외부 DB, 기관 내부 시스템을 조사한 것은 아니다. 자료를 새로 수집하거나 기관에 연락하지 않았다.

- raw_stock의 DAT 13개 헤더를 모두 확인했다. 2018~19년 파일 3개는 16개 열, 최근 파일 10개는 18개 열이다. 날짜는 재고마감일이고, 수량은 입고·이동·정상출고·반품·폐기·보정 등이다. 최근 파일에는 구입처코드와 구입단가가 추가로 있다. 진료·검사·접종 건수, 예약 현황, 실제 대체 사용 이벤트는 이 헤더에 없다.
- data/mapping/item_forecast_classification_approved.csv는 4,969행이며 reviewer는 codex_external_evidence_pipeline, review_status는 approved다. 분류의 자동 승인 기록이지 실제 대체 사용의 현장 확인 기록이 아니다.
- data/mapping/institution_id_mapping.csv는 3,530행이며 mapping_status는 verified_by_on_hand_agreement다. 내부 DB 재고 대조를 근거로 남긴 연결이다. 과거 문서의 '0행' 설명과 달리 현재 파일은 채워져 있다. 그러나 내부 ID와 공개 의료기관 코드가 같다는 증거는 없으므로 공개 진료 통계를 임의 연결하지 않는다. 이번에 DB 대조를 다시 실행한 것은 아니다.
- data/handoff의 censored_demand, zero_stock_reason 등은 재고 기록에서 계산한 값이다. 실제 진료 필요량, 미충족 요청 건수, 대체 사용 이벤트로 바꾸어 해석할 수 없다.
- src/loading/build_ingredient_tiers.py에는 약성분 DAT 처리 코드가 있으나, 현재 점검한 raw_stock와 data 아래에서 해당 원본이나 drug_ingredient_master/ingredient_tiers 파일을 찾지 못했다. 코드가 있다는 사실을 데이터 확보나 실제 사용의 증거로 삼지 않는다. 성분 코드 일치만으로 임상적 대체 가능성을 인정하지 않는다.

따라서 추가 활동량을 연결한 학습은 현재 진행할 수 없다. WAPE의 새 개선 수치는 없다. 자료가 없다는 사실을 실제 활동량 0으로 처리하지 않는다.

## 기관 전달용 초안 — 아직 발송하지 않음

안녕하세요. TeamLex 의료재고 예측 연구의 후속 검증을 위해 자료 보유 여부를 문의드립니다.

현재 제공받은 재고 자료로 입출고와 재고 변화를 분석했으나, 사용량이 갑자기 증가하거나 품목별 사용 비중이 달라진 이유를 확인하기 어렵습니다. 다음 자료를 기존 재고 자료와 동일한 비식별 기관코드 기준으로 제공할 수 있는지 확인 부탁드립니다. 개인 식별정보나 환자별 진료기록은 요청하지 않습니다.

1. 기관·부서·월별 진료, 검사, 예방접종 등 업무 종류별 실제 건수. 각 수치의 집계 기간, 확정일, 누락 여부도 필요합니다. 여러 지표를 중복 합산하지 않도록 '인원'과 '건수', 초진·재진 포함 범위 등을 구분해 주시면 도움이 됩니다.
2. 가능하다면 당시 저장된 다음 달 예약·접종 사업 일정 및 예정 건수. 사후 확정 실적이 아니라 해당 시점에 알려져 있던 계획과 저장 날짜가 필요합니다. 과거 저장본이 없으면 없다고 알려주시면 됩니다.
3. 실제 대체 사용이 있었다면 발생일, 원래 품목코드, 대신 사용한 품목코드, 수량·단위와 사유를 확인할 수 있는 기록. 단순히 같은 분류에 속하는 품목 목록과 실제 대체 사용 기록은 구분해 주시기 바랍니다.
4. 가능하다면 품절로 공급하지 못한 요청량 및 기간. 재고가 0이었던 기간만으로는 미충족 수요가 있었다고 단정하기 어렵습니다.

우선 기존 최근 재고 자료와 겹치는 2024~2025년 자료의 보유 여부를 확인하고 싶습니다. 전체 제공이 어렵다면 동일 비식별 기관코드로 연결 가능한 일부 기관·기간을 안내 부탁드립니다. 필요한 경우 원기관명 공개 대신 기관 측에서 집계·연결한 비식별 결과만 제공해 주셔도 됩니다.

감사합니다.

## 수신 후 검증 순서

1. 기존 비식별 기관코드로 정확히 연결되는지 확인한다. 코드 순서, 기관명 추측, 유사한 지역이라는 이유로 연결하지 않는다. 기관 측 승인 연결이 필요하다.
2. 실제 0과 누락을 구분한다. 전체 집계가 아닌 부분 자료는 정상적인 월별 0이나 전체 활동량으로 쓰지 않는다.
3. 해당 예측 시점까지 알려진 수치만 사용한다. 8월 실적을 7월 말 예측에 넣지 않는다. 7월 말에 저장된 8월 예약 현황은 계획 자료로 구분할 때만 후보가 된다. 늦게 확정된 7월 실적 역시 7월 말에 이미 알려졌다고 가정하지 않는다.
4. 계획 수정본이 여러 개라면 예측 시점 이전 최신본 한 개를 선택해야 한다. 이번 검증 코드는 자료 형식과 시점만 검사하며, 수정본 선택·모델 입력 연결은 아직 구현하지 않았다.
5. 실제 대체 사용 여부와 허용되는 규격·단위는 기관 담당자 또는 적격 검토자의 근거를 확인한다. 파일에 역할 문자열이 있다는 것만으로 자격이나 사실이 검증되지는 않는다.
6. 연결률과 누락 사유를 보고한 뒤, 동일한 평가 표본에서 기존 모델과 새 입력 모델을 비교한다. 일부 기관만 연결되면 전체 점수로 일반화하지 않는다. 이미 반복 사용한 평가 기간 외에 새로운 검증 기간을 마련한다.

## 준비한 입력 검사 코드

scripts/validate_activity_evidence.py는 읽기 전용 JSONL 검사기다. 원본 CSV/엑셀을 직접 변환하거나 기관 데이터를 수정하지 않는다. 내부 분석용으로 변환한 뒤 사용할 필드 명세는 다음과 같다.

활동량 공통 필드: institution_code(기존 비식별 기관코드), department(부서), available_at(당시 이용 가능 시각과 시간대), evidence_reference(출처 식별자).

활동량 추가 필드: period_start/period_end(집계 기간), activity_type(업무 종류), record_type(actual 또는 planned), count(0 이상 정수), coverage_status(전체 집계가 확인된 경우 complete). 날짜는 YYYY-MM-DD, 시각은 시간대가 있는 ISO 8601로 전달한다. available_at은 이번에 파일을 내려받은 시각과 다를 수 있다.

대체 사용 필드: 위 공통 필드와 event_date, from_item_code, to_item_code, quantity, unit_code, confirmation_role. 역할은 institution_staff 또는 qualified_reviewer로 제한하지만 실제 증거와 검토 자격은 별도로 확인해야 한다. 이 형식은 사건의 기본 필드만 확인하며 사유·단위환산·임상적 동등성을 자동 검증하지 않는다.

예상하지 못한 추가 열은 개인정보가 섞이지 않도록 차단한다. 개인 이름·식별번호·연락처를 모델 입력에 포함하지 않는다. 텍스트 필드 안의 개인정보까지 자동 탐지하는 프로그램은 아니므로 기관의 비식별 검토를 대신할 수 없다.

실행: `python scripts/validate_activity_evidence.py --activity <활동량.jsonl> --substitution <대체기록.jsonl> --institution-codes <승인된_비식별기관코드목록.json> --as-of <예측시점과시간대>`

기관코드 목록은 JSON 문자열 배열이며 기존 코드에 대한 기관 측 연결 근거가 있어야 한다. 두 종류 자료의 상태를 독립적으로 출력한다. 한 자료가 없어도 다른 자료의 점검 결과는 출력되지만 전체 명령은 성공으로 처리하지 않는다. 둘 다 있어야만 모든 연구를 시작할 수 있다는 의미는 아니다.

자료를 지정하지 않은 실제 실행은 activity/substitution 모두 missing, training_started=false를 출력하고 비정상 종료코드로 차단했다. 이는 의도된 동작이다. 가짜 활동량을 만들어 학습하지 않았다.

테스트 8개를 통과했다. 실제 0과 결측, 사후 공개, 부분 집계, 예상하지 못한 열, 미연결 기관, 시점·시간대, 미리 알려진 미래 계획, 자동 승인과 현장 확인의 구분을 검사했다. 테스트의 가상 값은 단위 테스트 안에만 있으며 연구 데이터가 아니다.

## 현재 필요한 사용자 확인

재고 DAT 외에 기관에서 따로 받은 진료·접종 실적, 예약, 대체 사용 자료가 있다면 해당 경로를 알려주면 된다. 없다면 위 요청안을 기관 담당자에게 전달하여 보유 여부와 제공 가능 범위를 확인해야 한다. 그 전에는 신규 활동량 모델을 실행하거나 성능 개선을 주장할 수 없다.
