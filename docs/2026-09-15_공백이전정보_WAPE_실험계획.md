# 공백 이전 관측 정보를 추가한 전체 표본 비교

## 가설과 앞선 실험과의 차이

기존 전처리는 기록이 없는 달을 0으로 오인하지 않도록 연속 구간을 나눈다. 이 규칙은 유지한다. 다만 동일 품목의 이전 구간에서 실제 관측한 수량이 현재 지연값·이동평균에 반영되지 않는 경우가 있어, 이전 구간의 마지막 값·평균·관측 수·경과 개월을 별도 입력한다. 결측 월을 채우거나 과거 관측을 최근 관측으로 가장하지 않는다.

집단별 TabM 학습은 같은 74개 변수를 나눠 학습했으며 실패했다(PR121). 이번 실험은 기존 LightGBM의 조건을 유지하고 실제 과거 정보를 4개 추가해 정보 부족 가설을 분리해 검증한다. 모델 계열 변경 실험이 아니다. 원래 기준 모델과 서비스는 그대로 보존한다.

입력은 PR119에서 생성한 gap-memory-20260915/outputs/gap_memory_v1/prepared.parquet이다. 동일 기관·부서·품목·알려진 표준 정의·단위가 유지되고 바로 이전 구간의 마지막 관측이 2~12개월 전일 때만 연결한다. 단위 변경 중간 구간을 건너뛰지 않는다. 생성 코드의 미래값 비의존·단위 변경·공백 처리 검사를 다시 실행한다. 추가 변수의 결측값은 학습용 중앙값으로 채우지 않고 LightGBM에 누락으로 전달한다. 기존 74변수 전처리는 기존과 같다.

## 사전 고정 조건

74변수 direct_full 모델과 동일한 전체 적격 자료·시계열 분할·LightGBM 파라미터를 사용한다. 2025년 4월까지 학습해 5~6월 검증, 7월까지 학습해 8~9월 검증을 순차 진행한다. 원래 수량의 절대오차를 최소화하며 두 검증의 합산 WAPE로 기존 모델과 후보를 선택한다. 평가 표본을 연결 성공 행으로 제한하지 않는다. 연결·미연결 결과는 부가 진단으로 함께 기록한다.

검증 결과를 저장한 뒤에만 10~12월 재사용 평가를 실행한다. 이 자료는 독립 확증이 아니다. 재사용 평가를 본 뒤 파라미터를 바꾸지 않는다. 검증 4개 월의 월 단위 부트스트랩 2,000회로 개선량의 95% 구간을 계산하되 월 수가 적어 불확실성이 크다. 양의 개선 비율을 실제 개선의 확률로 단정하지 않는다. WAPE와 BIAS·월별 결과를 함께 보고, 개선 근거가 없으면 해당 설정을 기각한다.

기준 모델의 각 검증 WAPE가 기존 수치를 재현하는지 먼저 확인한다. 원래 준비 자료는 float32 정답을 보존하고 두 모델에 같은 값을 사용하므로, 원본 고정밀도 평가 파일과의 극미한 반올림 차이는 성과로 해석하지 않는다.

CPU 2스레드, BLAS 1스레드, 한 번에 한 모델만 실행한다. 100개 트리마다 로컬 체크포인트를 별도 저장하고 최종 모델과 전처리 정보를 저장한다. 메모리 여유 1.5GiB 미만 또는 한 단계 2시간 초과 시 자신의 하위 프로세스만 종료한다. 오류 후 무한 재실행하지 않으며 재부팅 후 자동 재시작하지 않는다. 체크포인트는 보존용이고 자동 이어 학습 기능은 없다.

## 기대 범위와 제한

이전 감사에서 해당 정보 연결 검증 행은 40,617개이며 전체 기준 절대오차의 약 11.72%를 차지했다. 해당 행만 완벽히 고쳐도 전체 WAPE 하한은 약 31.33%다. 이는 실제 개선 예측이 아니고, 전체 재학습이 다른 행에 미치는 효과까지 제한하는 상한도 아니다. 이 정보 하나로 25%를 약속할 근거는 없다.

본 가설의 직접 근거는 [PR119의 실제 관측 연결 및 검사](https://github.com/DGU-TeamLex/ai/pull/119)와 [PR117의 관측 공백 감사](https://github.com/DGU-TeamLex/ai/pull/117)다. 논문이 이번 변수의 효과를 입증했다고 주장하지 않는다. 신규 정보 연결의 실제 개선 여부를 검증하는 실험이다.

실행 코드는 scripts/gap_wape_experiment.py이며, 결과는 outputs/gap_wape_v1의 status.json, 각 단계 로그, results.json에 기록한다. 원본 데이터·기관 식별값·행별 예측·모델 파일은 로컬에만 보관한다.
