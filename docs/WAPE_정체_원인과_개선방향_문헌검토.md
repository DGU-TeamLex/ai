# 사용량 예측 오차의 원인과 개선 방향

## 1. 결론

현재 결과만으로 WAPE 35~37%가 데이터의 한계라고 판단할 수 없다. 반대로 모델을 더 크게 만들거나 입력 열을 늘리면 20%대로 내려간다고 약속할 근거도 없다. 다음 연구는 새로운 모델 이름을 추가하는 것보다, 실제 절대오차가 집중된 기록을 설명할 정보를 찾고 그 정보에 맞는 학습 구조를 비교하는 방향이 타당하다.

기존 사용량 모델의 2025년 10~12월 평가 359,335행을 재계산한 결과 WAPE는 35.7032%, BIAS는 -7.5925%였다. 실제 사용량이 0인 행은 24.42%지만 그 행에서 발생한 오차는 전체 절대오차의 2.05%였다. 반면 오차가 큰 상위 5% 행은 전체 절대오차의 48.92%를 차지했다. 따라서 0 사용량을 예측하는 기능만 강화하는 것보다는 양의 사용량, 특히 큰 오차가 반복되는 품목의 사용 규모를 설명하는 것이 전체 WAPE 개선에 더 직접적이다.

이것은 인과관계를 규명한 결과가 아니라 저장된 예측의 사후 진단이다. 큰 오차가 기록 오류인지, 실제 사용 급증인지, 관측되지 않은 진료·접종 일정 때문인지는 추가 확인이 필요하다. 큰 오차 행을 제거해 점수를 낮추거나 평가 결과를 보고 해당 행만 우대하는 것은 올바른 개선이 아니다.

## 2. 37%와 35.70%는 같은 시험 점수가 아니다

입력 변수 확장 실험의 초기 기준 WAPE 37.4094%는 2025년 5~6월 242,034행의 검증 점수다. 기존 35.7032%는 2025년 10~12월 359,335행의 평가 점수다. 학습 마감 시점과 대상 월이 다르므로 두 수치 사이의 차이를 모델의 개선·악화로 해석하면 안 된다.

첫 검증 구간에서는 기존 51개 변수에 사용 간격·최근 추세를 추가했을 때 37.10%, 동종 품목 정보를 추가했을 때 37.19%로 낮아졌다. 달력만 추가한 경우 37.64%, 사용 패턴과 달력을 함께 추가한 경우 37.61%였다. 이는 중간 결과이며, 최근 구간의 검증과 후보 선택 후 평가가 남아 있다. 첫 구간에서 유리한 후보가 최종적으로도 유리하다는 보장은 없다.

WAPE는 정답 합계로 오차를 나누므로, 평가 기간의 사용량 규모가 달라지면 같은 절대오차에서도 값이 달라진다. 서로 다른 기간의 숫자를 나란히 놓는 것만으로 성능을 판단하지 않는다. 기존 WAPE 목표는 유지하되 같은 행·같은 기간에서 비교하고, 월별 값과 오차 합계도 함께 확인한다.[1]

## 3. 실제 오차가 집중된 부분

아래 결과는 모두 기존 사용량 모델의 2025년 10~12월 저장 예측에 대한 진단이다. 행은 기관·부서·품목·예측 시점의 조합이다. 서로 다른 조건의 부분집합은 겹칠 수 있으므로 비율을 모두 더하지 않는다.

### 사용이 발생한 기록에서 대부분의 오차가 발생했다

사용량이 0인 87,750행에서 발생한 절대오차는 WAPE 0.7310%p에 해당한다. 나머지 양의 사용량 271,585행에서는 34.9722%p가 발생했다. 양의 사용량 예측을 전혀 바꾸지 않고 실제 0인 행만 완벽하게 고친다는 비현실적인 가정에서도 WAPE는 약 34.97%까지 낮아질 뿐이다. 이것은 전체 모델의 이론적 한계가 아니라, 해당 부분집합의 오차만 제거하는 가상 계산이다.

과거 6개월 중 절반 이상 사용량이 0이었던 행도 전체 절대오차의 3.48%만 차지했다. 따라서 간헐 수요 전용 모델은 특정 품목에서는 의미가 있어도, 이번 전체 WAPE를 크게 개선하는 첫 번째 수단이라고 단정하기 어렵다. 발생 여부와 양의 사용량 규모를 함께 개선하는 모델의 가능성까지 부정하는 것은 아니다.

### 큰 오차가 소수 기록에 집중됐다

절대오차 순으로 정렬한 상위 1% 행은 전체 오차의 24.79%, 상위 5%는 48.92%, 상위 10%는 63.99%를 차지했다. 기관·부서·품목별로 오차를 합산해도 상위 5% 조합에서 전체 오차의 47.58%가 발생했다.

이 비중은 평가가 끝난 뒤 확인한 값이다. 앞으로 예측할 때 어느 기록이 큰 오차를 낼지는 미리 알 수 없다. 실제 개선 실험에서는 과거 사용 규모·변동성·기록 길이로 집단을 정하고, 과거의 시점별 검증에서 오차가 집중되는 조건이 반복되는지 확인해야 한다.

### 급증 구간은 중요한 후보지만 사후 정의다

최근 3개월 평균이 양수이고 실제 다음 달 사용량이 그 평균의 두 배를 넘은 행은 전체의 9.65%였다. 이 행들의 오차는 전체 절대오차의 25.82%였다. 큰 사용량 변화에 대응할 정보가 중요할 가능성을 보여준다.

다만 다음 달 실제값으로 만든 이 조건은 진단용이지 입력 변수가 아니다. 같은 조건을 모델 선택이나 예측기에 그대로 넣으면 미래 정보를 사용하게 된다. 예측 가능한 대안은 과거 증가 속도, 최근 사용일 빈도, 과거 대량 사용 빈도, 사전에 정해진 일정 등이다. 월별 합계만으로 모든 급증을 미리 알 수는 없다.

### 과소예측과 과대예측이 동시에 존재한다

과소예측에서 발생한 절대오차는 전체의 60.63%, 과대예측은 39.37%였다. 따라서 BIAS가 음수라는 이유로 모든 예측을 같은 비율로 올리면, 이미 많이 예측한 기록의 오차가 커질 수 있다. BIAS 보정과 WAPE 개선을 같은 일로 취급하지 않는다.

## 4. 자료가 많아도 개별 품목의 이력은 짧다

평가 행의 39.99%는 해당 시점까지 연속된 관측 이력이 6개월 미만이었다. 이력 길이의 중앙값은 8개월, 25분위는 3개월이었다. 이는 기관의 실제 운영 기간이나 모든 과거 기록의 길이가 아니라, 현재 특성표에서 끊기지 않고 이어진 구간의 길이다.

이런 자료에서 전체 학습 행이 수백만 개라는 사실만으로 개별 품목의 연간 계절성을 충분히 학습했다고 볼 수 없다. 월별 12개 관측을 요구하는 신경망에는 짧은 기록을 채워 넣는 처리가 빈번하게 필요할 수 있다. 오래된 2018~2019년 자료도 중간의 공백을 자동으로 연결해 현재 품목의 연속 이력으로 만들 수 없다.

현재 확장 실험의 8~9월 검증 자료에서 `lag_12`의 결측 비율은 59.21%였다. `same_month_last_year`는 코드상 `lag_12`를 복사한 열이므로 별도의 정보원이 아니다. 열이 51개라도 51종류의 독립적인 설명 정보가 있는 것은 아니다. 평균·표준편차·시차 변수 상당수는 동일한 사용량 기록에서 계산된다.

동종 품목 평균도 검증 자료의 75.58%에서 계산되지 않았다. 정확한 계열·규격·단위를 요구하므로 정보가 연결되는 범위가 제한된다. 단순히 연결률을 높이려고 단위나 규격 조건을 제거하면 다른 물건을 섞는 문제가 생긴다. 정확한 연결과 충분한 표본을 함께 확보해야 한다.

## 5. 모델이 얕아서 생긴 문제인가

현재 비교의 기준은 LightGBM이며 말단 구간 수 최대 249, 학습 횟수 최대 1,999회다. 신경망의 층수와 나무의 깊이는 다른 개념이다. 말단 구간 수 249를 깊이 249라고 표현해서도 안 된다. 기존 저장 모델에서 확인한 `max_depth=-1`은 별도의 최대 깊이 제한을 두지 않는 설정이었다.

첫 검증 기준 모델의 최적 반복은 1,990회였다. 1,200회부터 1,900회까지 검증 MAE도 47.3489에서 47.1806으로 계속 내려갔다. 따라서 최대 반복 횟수가 너무 이른 제한일 가능성을 시험할 근거는 있다. 그러나 마지막 구간의 감소폭은 작으며, 반복을 늘리면 WAPE가 크게 낮아진다는 증거는 아니다.

권장 검사는 가장 유망한 입력 구성에 대해서만 최대 반복을 늘리고 같은 조기 종료 규칙을 적용하는 것이다. 동시에 학습 오차와 검증 오차를 함께 저장한다. 학습 오차만 줄면 과적합 가능성이 있고, 둘 다 더 줄면 아직 학습량이나 표현력을 늘릴 여지가 있다. 현재 로그만으로 과소적합과 과적합을 확정할 수 없다.

## 6. 문헌이 지지하는 것과 지지하지 않는 것

### M5: 좋은 결과는 모델 이름 하나보다 전체 설계에서 나왔다

M5 정확도 대회 결과 논문은 소매 판매 자료에서 LightGBM과 여러 모델 결합의 유효성을 보고한다. 상위권 방법은 달력·가격·상품 계층 등 문제에 맞는 정보를 활용했다. 2위 구현도 하위 수준 예측, 상위 수준 예측, 두 수준을 맞추는 단계를 분리해 공개했다.[2][3]

TeamLex에 적용할 수 있는 부분은 품목별 기록과 같은 계열의 합계 패턴을 함께 사용하는 설계다. 다만 M5는 일별 소매 판매와 WRMSSE 평가이며, TeamLex는 월별 의료 물품 기록과 WAPE 평가다. 대회 순위나 점수를 직접 옮겨 기대 성능으로 쓰면 안 된다. 논문 원문 전체가 아닌 공개된 초록·서론·결과 요약과 참가자의 공개 구현 설명을 근거로 검토했다.

### 여러 품목을 함께 학습하되, 무조건 따로 나누지는 않는다

Montero-Manso와 Hyndman은 여러 시계열을 함께 학습하는 전역 모델이 서로 다른 특성을 가진 자료에서도 유효할 수 있음을 이론과 실험으로 설명했다. 따라서 품목이 서로 다르다는 이유만으로 품목마다 모델을 하나씩 만드는 것이 정답은 아니다.[4]

TeamLex에는 전체 공통 모델을 유지하면서 과거 사용 규모·변동성·기관 특성별 보정 모델을 비교하는 방식이 적절한 후보가 된다. 표본이 작은 집단은 공통 모델에 더 의존하게 해 과도한 세분화를 막는다. 이러한 분할이 실제로 낫다는 것은 별도 검증해야 한다.

### 발생 시점과 사용 규모를 분리하는 연구

Türkmen 등의 연구는 사용 사이의 시간 간격과 발생 규모를 별도로 모델링하는 확률적 틀을 제안했다. 부품·소매 자료에서 다양한 결과를 비교했으며, 짧은 학습 이력에서는 신경망이 항상 유리하지 않았다. Rožanec와 Mladenić도 수요 발생 여부와 규모를 나누는 접근을 연구했다.[5][6]

이 근거는 연속 0, 마지막 사용 이후 경과 기간 같은 변수 설계에 도움이 된다. 그러나 TeamLex의 진단에서는 0인 행의 오차 비중이 작았다. 전체 WAPE를 낮추려면 발생 여부뿐 아니라 양의 사용 규모에서 발생하는 오차를 함께 줄이는지 확인해야 한다. 확률과 평균을 곱하는 방식이 WAPE에 최적이라는 주장은 이 논문들로 뒷받침되지 않는다.

### 시간·품목별 합계를 함께 예측하는 연구

Kourentzes와 Athanasopoulos는 시간 집계 수준을 바꾸면 불규칙한 자료의 구조를 더 잘 드러낼 수 있다고 보고했다. MinT 연구는 하위 예측의 합과 상위 예측을 맞추는 방법을 제안하며, 편향이 없다는 가정 아래 제곱오차를 다룬다.[7][8]

TeamLex에서는 월별 품목 예측과 같은 단위·품목 계열의 합계 예측을 결합하는 실험이 가능하다. 그러나 분기 합계를 예측한 뒤 미래 실제 비율로 월별 분배하면 안 된다. 비율도 과거 자료로 정해야 한다. 또한 MinT는 WAPE 최소화를 보장하지 않으며, 합계의 중앙값이 각 항목 중앙값의 합과 같지도 않다. 자동 도입보다 별도 후보 비교가 필요하다.

### 깊은 모델에 대한 연구 결과는 조건에 따라 다르다

Zeng 등의 DLinear 논문은 당시 장기 시계열 예측 벤치마크에서 단순 선형 모델이 복잡한 Transformer보다 좋은 결과를 낼 수 있음을 보였다. 반면 iTransformer는 입력의 표현 방식을 바꿔 다변량 예측 성능을 개선했다.[9][10]

두 결과는 모순이라기보다 입력·구조·과제·비교 조건에 따라 결과가 달라진다는 사례다. 둘 다 TeamLex의 짧고 끊긴 월별 이력에서 특정 모델의 우위를 보장하지 않는다. 최근 실행은 주로 사용량만 입력한 설정이었으므로, 추가 입력을 적절하게 연결한 신경망의 가능성은 아직 검증되지 않았다.

### 품절로 관측되지 않은 수요

Trapero 등의 연구는 재고가 없을 때 판매량이 실제 수요를 충분히 나타내지 않는 문제를 다루고, Tobit Kalman filter를 제안한다. 실제 수요가 관측되지 않는 상황에서는 단순 판매량 예측과 수요 추정이 달라진다.[11]

TeamLex에서도 같은 가능성을 확인해야 하지만 현재 품절 비율이 양수인 직전 월 기록은 평가 행의 2.02%, 오차의 1.60%였다. 이 지표의 정확성도 별도 확인이 필요하다. 따라서 현재 지표만으로 품절을 전체 WAPE 정체의 주원인이라고 단정하거나, 관측 사용량을 임의로 늘려 정답을 바꿔서는 안 된다. 해당 논문은 공개 초록·서론·문제 정의 범위에서 검토했다.

## 7. WAPE에 맞는 수식과 주의점

비음수 사용량에 대한 평가식은 다음과 같다.

\[
\mathrm{WAPE}=100\frac{\sum_i|y_i-\hat y_i|}{\sum_i y_i}.
\]

같은 평가 행에서는 분모가 고정이므로 MAE 또는 절대오차 합을 최소화하는 것과 동일하다. L1 손실은 이 목표에 맞는다. WAPE가 잘 줄지 않는다고 L1을 잘못된 손실로 단정하지 않는다. 대신 입력과 학습 조건이 조건부 중앙값을 충분히 추정하는지 살핀다.[1]

발생 여부와 사용 규모를 나눈다고 가정하면, 발생 확률을 p, 발생 시 사용량의 누적분포를 G라고 할 수 있다. 평균을 예측하려면 p와 발생 시 평균을 곱한다. 하지만 절대오차 목표의 중앙값은 다르다. p가 0.5 이하이면 0이 중앙값 후보이고, p가 0.5보다 크면 G의 `1 - 0.5/p` 분위수를 사용한다. 이는 0에 확률이 있고 나머지가 양의 값인 혼합분포의 중앙값에서 도출한 식이다. 실제 p와 G는 학습해야 하며, 이론식을 적용했다고 성능이 보장되지는 않는다.

WAPE를 낮추기 위해 실제 사용량에 비례한 가중치를 한 번 더 곱하는 것도 자동으로 맞는 방법은 아니다. 이미 고정 분모 아래 절대오차 합을 최소화하므로, 추가 가중치는 다른 목적함수를 만든다. 품목별 표준화를 적용할 때에도 원래 단위 오차의 비중이 어떻게 바뀌는지 명시해야 한다.

또한 특성표의 단위 코드는 9종류였다. 본 진단은 단위를 새로 환산하지 않고 기존 평가 계약을 그대로 재현했다. 단위 코드가 여러 개라는 사실만으로 기존 수량이 잘못됐다고 결론 내릴 수는 없지만, 공통 단위 환산 여부는 검증 대상이다. 예를 들어 동일 실물을 개수로 기록하느냐 상자로 기록하느냐에 따라 전체 합계에서의 비중이 달라질 수 있다. 원래 점수를 보존한 채 단위별 오차와 표준 단위 변환 근거를 추가 점검해야 한다.

## 8. 예측을 섞는 방법도 직접 확인했다

재학습 없이 기존 모델과 N-HiTS·TimesFM·PatchTST·Chronos-2 예측을 각각 섞었다. 새 모델의 비중은 0부터 1까지 0.05 간격으로 탐색했고, 8~9월 검증 WAPE가 가장 낮은 비중을 선택했다. 평가 월의 정답으로 비중을 고르지 않았다. 예측 결합은 연구에서 널리 다뤄지지만 효과는 자료에 따라 다르다.[12]

검증에서 선택된 새 모델 비중은 N-HiTS 10%, TimesFM 15%, PatchTST 10%, Chronos-2 15%였다. 각각의 10~12월 평가 WAPE는 35.7006%, 35.7244%, 35.7571%, 35.6914%였다. 기존 모델의 35.7032%와 비교하면 개선은 매우 작거나 오히려 악화됐다.

Chronos-2 조합의 검증 WAPE는 35.6063%로 네 조합 중 가장 낮았다. 평가 개선폭은 약 0.0118%p에 불과하므로 의미 있는 성능 향상이라고 주장하지 않는다. 별도의 불확실성 검정은 수행하지 않았다. 결합 가능성 자체를 부정하지 않지만, 단순히 전체 품목에 같은 비율로 섞는 것이 큰 개선책이라는 기대는 낮춰야 한다.

## 9. 다음 실험의 우선순위

### 우선순위 1: 큰 오차가 반복되는 조건을 과거 자료에서 찾는다

평가 이후에 알게 된 상위 오차 행은 원인 조사에만 쓴다. 학습 단계에서는 과거 사용량 규모, 사용 빈도, 변동성, 기록 길이로 집단을 정한다. 여러 과거 검증 구간에서 같은 집단이 반복해서 큰 오차를 만드는지 본다. 특히 단위 변경, 코드 변경, 일괄 기록, 대량 입고 후 일시적 사용 증가를 구분한다.

실제 대량 사용을 오류라고 삭제해서는 안 된다. 확인된 입력 오류만 근거와 수정 전후 결과를 남기고 정정한다. 새로운 변수의 효과는 전체 점수와 해당 집단 점수를 함께 기록한다.

### 우선순위 2: 월 합계에 없던 정보를 기존 상세 기록에서 추출한다

기존 상세 자료를 재사용할 수 있다면 최근 월의 실제 사용 발생일 수, 건당 사용량, 최대 일사용량, 월말 집중도, 최근 7일·14일 사용 추세 등을 후보로 만든다. 월 합계가 같은 두 품목이라도 매일 일정하게 사용했는지 하루에 몰아서 처리했는지 구분할 수 있다.

이번 조사에서는 처리된 월별 파일의 존재를 확인했지만 원본 DAT의 위치·필드·시간 단위와 코드 연결을 다시 검증하지 않았다. 따라서 이 변수들이 지금 바로 생성 가능하다고 확정하지 않는다. 먼저 기존 상세 자료에 실제 사용일과 기록일이 구분되는지 확인해야 한다. 미래 월의 상세 기록을 입력으로 사용하지 않는다.

### 우선순위 3: 공통 모델과 집단별 보정을 비교한다

전체 품목을 함께 학습한 모델을 기준으로 두고, 과거 사용 규모와 변동성으로 정한 집단에 보정 모델을 추가한다. 표본이 충분한 집단만 별도 학습하고, 부족한 집단은 공통 모델을 사용한다. 집단별 모델이 전체 모델보다 좋은지 여러 시점에서 확인한다. 원시 품목 코드를 무조건 추가하거나 각 품목에 별도 대형 모델을 배정하는 방식은 우선하지 않는다.

### 우선순위 4: 학습 반복 제한과 원래 단위 손실을 점검한다

현재 입력 확장 실험이 끝난 뒤 가장 유망한 후보에 대해서만 반복 횟수 상한을 늘린다. 학습·검증 오차를 함께 기록하고, 더 복잡한 모델이 실제로 더 많은 정보를 배우는지 확인한다. 신경망에는 지원되는 기관·품목 특성과 과거 재고 정보를 연결하되, 입력만 같다고 모든 모델의 조건이 완전히 동일해지는 것은 아니라는 점을 명시한다.

### 우선순위 5: 같은 계열의 합계와 개별 예측을 함께 활용한다

정확하게 연결된 품목 계열·규격·단위 범위에서 합계 예측과 개별 예측을 결합한다. 큰 집계의 변동이 상대적으로 안정적이라는 가설을 검증한다. 연결이 안 되는 품목은 별도로 남기고 합계 예측으로 덮어쓰지 않는다. MinT 등 기존 방법을 도입하더라도 WAPE를 따로 확인한다.

이 우선순위는 비용 대비 확정된 개선률 순위가 아니다. 실제 오차 구조와 자료 접근 가능성을 고려한 조사·실험 순서다. 현재 진행 중인 12개 학습을 중단하거나 고부하 작업을 추가하지 않았다.

## 10. 무엇이 확인돼야 개선이라고 말할 수 있는가

후보는 과거 시점별 검증에서 선택하고, 기준 모델과 같은 정답·같은 품목·같은 단위로 비교한다. 전체 WAPE만 아니라 월별 개선 방향과 BIAS를 함께 본다. 특정 기관에만 개선이 집중됐는지, 단위가 다른 대량 품목 하나의 영향인지도 확인한다.

월이 두세 개뿐이면 월 단위 재표집 신뢰구간은 정보가 제한된다. 행 수가 많다는 이유로 각 행을 독립 표본처럼 다뤄 확신을 과장하지 않는다. 가능한 과거 월로 검증 시점을 늘리고, 마지막에는 새 월 자료가 확보됐을 때 다시 확인하는 것이 필요하다. 이미 여러 번 사용한 10~12월 결과를 새로운 독립 검증이라고 표현하지 않는다.

35.7032%를 30%로 낮추려면 같은 분모에서 전체 절대오차를 약 16.0% 줄여야 한다. 이것은 꽤 큰 변화다. 0.2~0.3%p 개선을 무의미하다고 버릴 필요는 없지만, 작은 변화들을 단순히 더하면 30%가 된다고 가정해서도 안 된다. 서로 같은 오차를 개선하거나 함께 적용할 때 악화될 수 있기 때문이다.

## 11. 조사 범위와 재현 자료

이번 검토는 전 문헌에 대한 체계적 문헌고찰이나 메타분석이 아니다. 실제 진단에서 확인한 오차 집중, 짧은 이력, 불규칙 사용, 예측 결합과 관련된 대표 연구·공식 구현을 중심으로 검토했다. 각 연구의 의료 분야 전이 가능성과 목표 지표 차이를 구분했다. 일부 출판사 페이지는 전문 접근이 제한돼 공개 초록·서론·문제 정의까지만 확인했으며 그 제한을 해당 절에 표시했다.

원본 개인·기관별 기록은 보고서나 Git에 포함하지 않는다. 분석 시점은 2026년 9월 14일이며, 입력 확장 실험 중간 점수는 최근 검증 구간 완료 전의 스냅샷이다. 원인 분석은 기존 저장된 2025년 10~12월 예측에 대한 결과다.

재현 코드는 `scripts/audit_wape_bottlenecks.py`다. 원본 프로젝트 경로를 `--source`, 새 출력 파일을 `--output`으로 지정한다. 기존 출력 파일은 덮어쓰지 않는다. 로컬 결과는 `outputs/wape_bottlenecks_v1.json`에 저장했다. 코드에서 평가 키 일치, 오차 분해 합계, BIAS 부호 일관성, 혼합 비중 범위를 점검한다.

근거 파일은 원본의 `outputs/stock_feature_table.parquet`, 이전 모델 비교의 `outputs/family_search_v1/evaluation.parquet` 및 모델별 예측 NPY, 입력 확장 실험의 `early_baseline51.json`, `feature_quality.json`, 학습 로그다. 모델 학습·서비스 갱신은 이번 문헌 조사에서 수행하지 않았다.
