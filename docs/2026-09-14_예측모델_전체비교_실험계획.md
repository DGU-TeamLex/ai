# 예측모델 계열별 전체 비교

## 목적

기존 모델만 조정하지 않고 다른 계열의 예측모델을 실제 실행해, 검증 WAPE가 낮은 후보를 찾는다. BIAS는 별도 지표이며 WAPE를 희생하여 특정 편향 수치에 맞추지 않는다. 운영 서비스나 기존 보고서의 채택 모델은 자동으로 변경하지 않는다.

비교 대상은 CatBoost, Croston-SBA, TSB, N-HiTS, PatchTST, TFT, Chronos-2, TimesFM 2.5, Prophet이다. CatBoost는 GPU의 실제 기본 설정과 Exact 잎 추정 방식 두 가지를 구분한다.

## 데이터와 공정한 비교

- 입력은 기존 프로젝트의 특성표, 백테스트 예측 CSV다. 외부로 기관 자료를 보내지 않는다.
- 학습 가능한 표 형태 자료는 3,039,785행이다. 2018~2019년 승인된 역사 자료와 2024년~2025년 6월 예측 원점 자료를 사용한다. 역사 자료 가중치는 기존 정책과 같은 1.0이다.
- 목표는 다음 달 사용량이다. 따라서 최근 학습 목표는 2025년 7월이다. 신경망은 이에 맞춰 2025년 7월까지 관측한 사용량을 학습한다.
- 평가 입력은 605,438행 전체이며 표본 추출하지 않는다. 2025년 8~9월 246,103행은 검증, 10~12월 359,335행은 평가다.
- 기관·부서·품목·예측 원점으로 기존 모델 예측을 일대일 연결하고, 실제값과 전체 행 수 일치를 확인했다.
- 시계열 입력은 예측 원점까지의 최대 24개월이다. 기록이 끊기면 구간을 나누며 누락 기간을 0으로 채우지 않는다. 새로운 관측을 입력할 수 있는 월별 한 달 앞 예측 조건이다.
- 같은 평가 행에서 `100 * sum(abs(actual-prediction)) / sum(actual)`로 WAPE를 계산한다. 일부 행만 완료된 모델에는 전체 점수를 붙이지 않는다.

전체 자료를 쓴다는 것은 모든 평가 행을 처리한다는 뜻이다. 신경망은 전체 학습 패널에서 미니배치를 뽑아 1,500회 갱신하므로 모든 학습 행을 정확히 한 번씩 방문했다는 뜻은 아니다.

## 모델별 설정과 출처

1. CatBoost: 25개 수치 입력과 기관·부서·품목군·품목계열·하위유형 5개 범주 입력. GPU MAE, 최대 1,500개 트리, 깊이 6, 검증 MAE 조기 종료. 설치된 1.2.10 모델의 실제 매개변수에서 기본 잎 추정 방식이 Gradient임을 확인했다. 처음 결과가 매우 큰 과소예측을 보여 원래 결과는 보존하고 Exact 방식을 별도 후보로 추가했다. Exact는 GPU Ordered boosting과 함께 사용할 수 없다는 실행 오류를 확인하여 이 후보는 Plain boosting을 명시한다. 따라서 순수한 단일 설정 변경 비교가 아니며, 설정 진단에 따른 사후 실험으로 기록한다. [GPU 학습](https://catboost.ai/docs/en/features/training-on-gpu), [잎 추정 설정](https://catboost.ai/docs/en/references/training-parameters/common).
2. Croston-SBA와 TSB: 사용이 불규칙한 품목을 위한 통계모델. TSB의 두 평활 계수는 0.1이다. 과거 사용 기록만으로 매 원점 한 달 앞을 예측한다. [공식 모델 문서](https://nixtlaverse.nixtla.io/statsforecast/src/core/models.html).
3. N-HiTS: 계층별로 시간 패턴을 학습하는 신경망. 입력 길이 12, 은닉층 128, MAE, 1,500회 학습. [공식 문서](https://nixtlaverse.nixtla.io/neuralforecast/models.nhits.html).
4. PatchTST: 시계열을 작은 구간으로 묶는 Transformer. 입력 길이 12, patch 4, stride 2, hidden 64, encoder 2, MAE, 1,500회 학습. [공식 문서](https://nixtlaverse.nixtla.io/neuralforecast/models.patchtst.html).
5. TFT: 이번 실행은 외부 입력 없는 사용량 단변량 설정이다. hidden 64, MAE, 1,500회 학습. TFT의 모든 외부변수 기능을 시험한 것은 아니다. [공식 문서](https://nixtlaverse.nixtla.io/neuralforecast/models.tft.html).
6. Chronos-2: `amazon/chronos-2`의 중앙값 예측. 추가 학습 없이 사용하고 cross_learning은 끈다. revision `29ec3766d36d6f73f0696f85560a422f50e8498c`. [공식 저장소](https://github.com/amazon-science/chronos-forecasting).
7. TimesFM: 이번 후보는 2.5 200M 모델이다. 설치 패키지 3.0.2와 모델 버전을 혼동하지 않는다. `google/timesfm-2.5-200m-pytorch`, revision `1d952420fba87f3c6dee4f240de0f1a0fbc790e3`. [공식 저장소](https://github.com/google-research/timesfm).
8. Prophet: 짧은 월별 이력에 추세 중심으로 적용하며 연·주·일 계절성을 끈다. 관측이 하나이거나 모든 값이 같으면 마지막 관측값을 유지하는 명시적 예외 정책을 쓴다. 동일한 입력 기록은 계산 결과를 재사용한다. 예외 정책 적용 행 수를 따로 보고한다. [공식 문서](https://facebook.github.io/prophet/docs/quick_start.html).

신경망은 학습 자료에서 계산한 단일 상수로 사용량 단위를 줄인다. 품목마다 각각 정규화하지 않아 원래 단위의 전체 절대오차 가중치를 보존한다. 각 모델의 내부 정규화 방식까지 모두 동일한 것은 아니다.

## 실행과 안전

격리 브랜치 `codex/model-family-search-20260913`, 별도 `.venv`. 기존 가상환경과 산출물을 건드리지 않는다. 고부하 모델은 순차 실행한다. GPU PyTorch 작업은 메모리 할당 비율 50%, CatBoost는 45%, CPU 스레드 2로 제한한다. 이는 GPU 전력 제한이나 발열 안전 보장을 뜻하지 않는다.

GPU 온도가 관측 시 82도 이상이거나 시스템 가용 메모리가 1.5GiB 미만이면 해당 작업 트리를 종료하고 전체 실행을 멈춘다. 모델별 1시간 예산 초과 시 예측 체크포인트를 남기고 다음 후보로 넘어간다. 하드웨어 전원 문제나 갑작스러운 종료를 이 감시로 모두 예방할 수는 없다.

모델 종료 후 15초 휴식. 예측은 모델별 NPY 파일에 순차 저장한다. 모델이 실패하거나 예산을 초과해도 미완료 행을 제외한 전체 점수를 만들어 내지 않는다. 학습 모델은 학습 완료 시 저장하므로 학습 도중 강제 종료되면 그 모델의 학습은 다시 필요할 수 있다. Prophet은 개별 학습 결과를 예측으로 저장하며 모든 개별 모델 객체를 보관하지 않는다.

## 재현 명령

사전학습 가중치의 공개 시점이 검증 기간 이후일 수 있으므로, 이 실험을 2025년 당시 이용 가능했던 모델의 실제 운영 재현이라고 해석하지 않는다. 가중치 revision을 고정한 현재 시점의 사후 비교다. 공개 모델의 모든 사전학습 자료에 대해서는 중복 여부를 검증하지 못했다.

```powershell
uv venv --python <기존_파이썬_경로> .venv
uv pip install --python .venv/Scripts/python.exe torch==2.11.0 --index-url https://download.pytorch.org/whl/cu128
uv pip install --python .venv/Scripts/python.exe -r requirements-model-search.txt
```

Chronos와 TimesFM 가중치를 위 revision으로 Hugging Face 캐시에 내려받는다. 학습 데이터는 업로드하지 않는다. 실행 때 같은 `HF_HOME`을 지정한다. 두 어댑터는 `local_files_only=True`라 가중치 준비가 안 되면 실패로 표시한다.

```powershell
python scripts/model_family_search.py prepare --source <기존_프로젝트> --output outputs/family_search_v1
python scripts/model_family_search.py suite --output outputs/family_search_v1 --steps 1500 --timeout 3600
python scripts/model_family_search.py aggregate --output outputs/family_search_v1
python -m unittest discover -s tests -p test_model_family_search.py
```

이미 준비한 출력 폴더는 `prepare`로 덮어쓰지 않는다. `suite`는 실행 잠금이 있으면 중복 시작을 거부한다. 재부팅 후 잠금이 남아 있으면 기록된 PID와 명령을 확인한 뒤 처리해야 한다. 결과 JSON이 존재하는 모델은 건너뛰고, 부분 예측은 채워진 배치를 재사용한다.

## 산출물과 해석 제한

`outputs/family_search_v1/comparison.csv`는 완료된 모델의 검증·평가 WAPE와 BIAS, 미완료 상태를 모은다. 모델별 `*_result.json`은 월별 결과, `*_status.json`은 진행 상태, `*.log`는 실행 로그다. `*_predictions.npy` 순서는 `evaluation.parquet`의 row_id와 같다. `suite_status.json`으로 전체 상태를 확인한다.

이것은 계열별 정해진 설정을 실행하는 1차 비교이지 전 모델의 전역 최적점을 찾는 실험은 아니다. 검증 구간에서 후보를 선택하고, 이미 여러 번 확인한 2025년 10~12월 결과는 사후 비교로 명시해야 한다. 학습·평가 자료의 시간적 한계와 모델별 입력 차이를 함께 해석한다. 새 후보의 WAPE가 낮아져도 새로운 월 자료에서 확인하기 전 운영 승격을 주장하지 않는다.
