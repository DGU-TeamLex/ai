# 일별 출고 기록을 이용한 입력 정보 개선

## 작업 변경

사용자 요청에 따라 이전 변동 폭·학습 횟수 비교 작업을 중단했다. 확인한 대기·감독·학습 프로세스 트리만 종료했으며 기존 모델 체크포인트와 로그는 삭제하지 않았다. 기존 status.json은 강제 중단 직전의 running 상태로 남을 수 있으므로 실제 프로세스와 함께 판단해야 한다. 중단 기록은 previous_experiment_stop.json에 남겼다.

이 브랜치는 원격 main에서 분리했고 PR #105의 입력 변수 실험 코드를 가져와 확장했다. 공유 작업트리, main/dev, 서비스 모델은 변경하지 않는다. 이 문서가 이 브랜치의 이전 실험 안내보다 우선한다.

## 새 정보

원본 정상출고 기록에서 기관·부서·품목·날짜별 양수 수량을 먼저 합산한다. 동일 날짜가 서로 다른 DAT 파일에 있어도 날짜 수는 한 번만 센다. 동일한 내용의 별도 기록을 임의 삭제하지 않는다.

추가 입력은 13개다.

- 기록이 있는 날짜 수, 양수 출고가 있는 날짜 수.
- 양수 출고 날짜의 평균·표준편차, 날짜별 최대 양수 출고량.
- 예측 시점 월 마지막 7일·14일의 양수 출고 합계와 양수 출고 날짜 수.
- 해당 월 양수 출고 중 마지막 7일의 비중.
- 해당 월 마지막 양수 출고일부터 월말까지의 일수.
- 정상출고 수량을 숫자로 해석하지 못한 기록 수, 음수 기록 수.

7일·14일은 월말을 포함한 달력 일수이며 해당 월 안에서 계산한다. 양수 출고가 없는 월의 평균·비중·마지막 양수 출고 간격은 0으로 단정하지 않고 결측으로 둔다. 수량 누락은 기존 처리와 일치하도록 양수 합계에 0을 기여하지만 별도 결측 기록 수로 표시한다.

재고마감일은 실제 환자 방문일이나 입력 시각으로 검증된 날짜가 아니다. 따라서 진료일 수·환자 수라는 이름을 사용하지 않는다. 늦게 입력한 기록을 과거 마감일로 기재했는지는 현재 필드로 판별하지 못한다.

## 정보 유출과 정합성 검사

예측 대상 월이 아닌 예측 시점 월(year_month)에만 연결한다. 다음 달의 활동 날짜 수나 실제 사용량은 입력에 쓰지 않는다. 과거 자료와 현재 자료를 모두 처리하며 학습 대상 행의 원본 양수 합계가 기존 model_demand_positive_sum과 모두 일치해야 학습으로 넘어간다. 연결 누락이나 합계 불일치가 있으면 중단한다. 상대 허용오차는 0.00001, 절대 허용오차는 0.0001이다.

일별 자료는 해당 월 안에서만 합산하므로 미래 월의 기록이 추가돼도 이전 월의 값이 바뀌지 않는다. 검증 전에 범주·결측 대체값을 학습 자료에서만 학습한다. 같은 기록에 대한 중복 날짜 합산, 음수와 결측, 미래 월 분리, 합계 불일치 차단을 테스트한다.

## 비교 실험

사용 패턴 포함 기존 61개 입력 모델(behavior)과 일별 기록 13개를 추가한 74개 입력 모델(behavior_daily)을 비교한다. LightGBM L1, 최대 1,999회, 최대 잎 수 249 등 모델 설정은 같다. 표본 축소 없이 각 후보를 두 시계열 검증 구간에서 학습해 총 4회 비교한다. 기존 모델을 재학습하는 것은 같은 환경에서 일별 정보의 효과만 비교하기 위한 대조군이다.

- 첫 구간: 목표 월 2025년 4월까지 학습, 5~6월 검증.
- 둘째 구간: 목표 월 2025년 7월까지 학습, 8~9월 검증.
- 두 검증 구간의 절대오차 합/실제량 합으로 후보를 선택해 먼저 저장한다. 이후 10~12월 평가에서 기준과 선택 후보의 WAPE·BIAS·월별 수치를 비교한다.

10~12월은 재사용한 평가 자료이고 이번 변수 설계에도 사후 진단의 영향을 받았다. 독립 확증 검증이 아니며, 성능 향상을 미리 보장하지 않는다. 서비스 모델 자동 교체, 평가 표본 삭제, 평가용 실제값에 맞춘 보정은 하지 않는다. 이번에는 규모별 보정까지 동시에 변경하지 않고 일별 입력 효과를 먼저 분리한다.

## 자원과 산출물

새 .venv를 사용하고 주요 라이브러리를 고정한다. CPU 2개, BLAS 스레드 1개로 순차 실행한다. 원본을 50,000행씩 읽어 작업 전용 DuckDB 파일에 저장하고 DB 메모리 한도는 1GB로 설정했다. 전체 자료를 한꺼번에 메모리에 올리지 않는다. 중간 DB 파일도 자동 삭제하지 않는다.

원본 처리 중 가용 RAM 2GiB 미만이면 중단한다. 감독 프로세스는 각 작업의 가용 RAM 1.5GiB 미만 또는 작업당 2시간 초과 시 해당 자식 프로세스를 중단한다. 체크포인트는 각 학습 완료 시 저장한다. 이 설정은 전원·발열 문제를 보장하지 않으며 강제 종료 재발 시 자동 재실행하지 않는다.

출력 경로는 outputs/daily_features_v1이다. status.json, daily_source_manifest.json, daily_monthly.parquet, manifest.json, feature_quality.json, 모델별 JSON/pkl, selection.json, test_results.json, 결과요약.md를 확인한다. stdout과 stderr는 outputs/daily_features.stdout.log와 outputs/daily_features.stderr.log다. 원본 및 DB·개별 예측 자료를 GitHub에 올리지 않는다.

실행: `.venv/Scripts/python.exe -u scripts/feature_expansion_experiment.py suite --source <원래 작업트리> --reference <기존 family_search_v1/evaluation.parquet> --output outputs/daily_features_v1`

기존 출력 경로가 있으면 실행이 거부된다. 같은 경로에 중복 실행하거나 체크포인트를 지워 재시작하지 않는다.
