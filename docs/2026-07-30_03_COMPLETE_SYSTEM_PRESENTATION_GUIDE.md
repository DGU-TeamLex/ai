# WeP-Stock AI 시스템 전체 구조·수식·가중치·운영 가이드

> 작성 기준일: 2026-07-30
> 작성자: 장세현
> 대상 독자: WeP-Stock 시스템을 처음 접하는 팀원, 중간점검 발표 청중, 백엔드·데이터·AI 협업자
> 문서 목적: 원본 재고 데이터부터 품목 표준화, 사용량 예측, 외부 위험 가중치, 목표재고·발주량, 2026년 8월 재고 시뮬레이션까지 한 문서로 설명한다.

---

## 0. 먼저 알아야 할 핵심 결론

이 시스템은 **현재고를 LightGBM이 직접 맞히는 구조가 아니다.**

1. `raw_stock/*.DAT`에서 월별 정상 사용량과 현재고를 만든다.
2. 물품명을 품목군·family·subtype·규격·단위로 표준화한다.
3. LightGBM과 기준선 모델이 **다음 달 사용량**을 예측한다.
4. 뉴스·원자재 가격·수출입 위험을 Module C 점수로 만든다.
5. 예측 사용량, 검토주기, 리드타임, 안전재고율, Module C 위험을 결합해 **목표재고량**을 계산한다.
6. 목표재고와 현재 재고위치를 비교해 **권장 발주량**을 계산한다.
7. 2026년 1월부터 8월까지는 실제 데이터가 없으므로 월별 예측과 가상 사용량을 재귀적으로 연결한 **합성 시뮬레이션**을 별도로 생성한다.

따라서 발표에서는 아래 네 값을 혼동하지 않아야 한다.

| 구분 | 의미 | 대표 컬럼 |
|---|---|---|
| 관측 현재고 | 원장에 실제 기록된 월말 재고 | `month_end_stock`, `current_stock` |
| 예측 사용량 | 다음 달 정상출고 예상량 | `predicted_usage` |
| 정책 목표재고 | 일정 기간을 보호하기 위해 보유해야 할 재고 | `base_stock`, `target_stock` |
| 미래 시뮬레이션 재고 | 가정한 발주·소비 흐름으로 계산한 월말 재고 | `predicted_month_end_stock` |

현재 대표 성능은 다음과 같다.

| 평가 범위 | 행 수 | WAPE | MAE | RMSE | BIAS_PCT |
|---|---:|---:|---:|---:|---:|
| 2025-10~12 최종 홀드아웃 | 359,335 | **37.1840%** | 52.3223 | 200.6530 | -3.4671% |
| 2025-08~12 전체 백테스트 | 605,437 | **36.9198%** | 50.2610 | 196.9116 | -5.0346% |

`WAPE 37.18%`를 “정확도 62.82%”라고 단순 변환해 발표하면 안 된다. WAPE는 전체 실제 사용량 대비 절대오차 비율이며, 분류 정확도나 개별 품목 적중률이 아니다.

## 0.1 용어 사전

이 절은 본문에 사용되는 용어를 **WeP-Stock에서 실제로 사용하는 의미**로 설명한다. 같은 단어가 일반적인 통계, 데이터베이스, 물류 업무에서 다른 뜻으로 사용될 수 있으므로 발표와 개발 논의에서는 아래 정의를 기준으로 한다.

### 0.1.1 먼저 구분해야 하는 핵심 용어

| 용어 | 이 시스템에서의 의미 | 혼동하면 안 되는 대상 |
|---|---|---|
| 사용량 | 정상적인 의료업무로 출고되어 소비된 수량 | 현재고, 구매량, 폐기량 |
| 예측 사용량 | 모델이 계산한 다음 달 정상사용량 | 모델이 직접 예측한 월말 재고 |
| 관측 현재고 | 원본 원장에 기록된 특정 시점의 재고 | 목표재고, 시뮬레이션 재고 |
| 기본재고량 | 외부위험을 적용하기 전, 보호기간 동안 필요하다고 계산한 정책 재고 | 현재 창고에 실제로 있는 수량 |
| 목표재고량 | 기본재고량에 외부위험 버퍼를 반영한 보유 목표 | 다음 달 사용량 |
| 권장 발주량 | 목표재고에서 현재 재고위치를 뺀 정책상 주문 제안량 | 반드시 자동 주문해야 하는 확정 수량 |
| 미래 재고 | 예측 사용량, 가상 사용량, 발주 가정을 순차 적용한 시뮬레이션 결과 | 미래에 실제로 관측된 재고 |
| 위험점수 | 사건이나 시장 상태가 위험한 정도를 `0~1`로 표현한 값 | 그 신호를 얼마나 반영할지 정하는 가중치 |
| 가중치 | 여러 입력 중 특정 입력의 반영 비율 또는 영향 강도 | 데이터 품질을 나타내는 신뢰도 |
| 신뢰도 | 데이터·매핑·신호를 믿을 수 있는 정도 | 위험 자체의 크기 |
| 임곗값 | 점수나 품질을 등급·통과 여부로 바꾸는 경계값 | 점수를 혼합하는 가중치 |
| 분류 정확도 | 정답 라벨과 분류 결과가 일치한 비율 | WAPE를 `100-WAPE`로 바꾼 값 |
| API 승인 | 외부 기관이 API 키 사용을 허용한 상태 | 품목-원자재 매핑 내용이 검증된 상태 |
| 매핑 승인 | 연결 후보가 규칙과 근거를 통과해 운영 사용이 허용된 상태 | 외부 API가 정상 호출되는 상태 |

### 0.1.2 데이터 구조와 식별 용어

| 용어 | 영문·표기 | 설명 |
|---|---|---|
| 원천 데이터 | source/raw data | 가공 이전에 기관에서 전달받은 재고 원장, 약성분 자료, 외부 뉴스·가격·무역 자료를 말한다. |
| `raw_stock` | raw stock directory | 이 프로젝트에서 재고 학습에 사용하는 유일한 내부 원천 폴더다. `device/` 자료는 사용하지 않는다. |
| DAT 파일 | `.DAT` | 확장자가 DAT인 원본 텍스트 데이터다. 실제 구조는 pipe 구분자 등 파일별 규칙으로 읽으며, 확장자만으로 바이너리 파일이라고 판단하지 않는다. |
| 행 | row/record | 한 번의 관측 또는 한 집계 단위를 표현하는 데이터 한 줄이다. |
| 컬럼 | column/field | 날짜, 기관, 품목, 출고량처럼 행이 가진 개별 속성이다. |
| 데이터 단위 | grain/granularity | 한 행이 무엇을 대표하는지 정의한다. 예를 들어 일별 원장의 grain은 `날짜 × 기관 × 부서 × 품목`이다. |
| 키 | key | 행이나 품목을 식별하거나 다른 표와 연결할 때 사용하는 컬럼 또는 컬럼 조합이다. |
| 복합키 | composite key | 기관코드와 물품코드처럼 두 개 이상의 컬럼을 함께 사용해야 유일해지는 키다. |
| 기관코드 | institution code | 보건기관을 식별한다. 같은 품목명이더라도 기관코드는 재고 소유 위치를 구분하기 위해 유지한다. |
| 부서코드 | department code | 한 기관 내부의 재고 관리 부서를 구분한다. |
| 물품코드 | item code | 기관 원장에 등록된 로컬 품목 식별자다. 기관이 다르면 같은 코드가 다른 물품일 수 있다. |
| 로컬 품목 | local item | `기관 × 물품코드`로 식별되는 실제 원장상의 품목이다. |
| 대표품목 | representative item | 여러 기관의 별칭을 하나의 의미 단위로 묶기 위해 만든 대표 레코드다. |
| 표준키 | standard key | 과거·현재 데이터에서 의미가 같은 품목을 학습 시계열로 연결하는 키다. |
| 별칭 | alias | 같은 표준품목을 가리키는 서로 다른 원본 물품명이다. |
| 스냅샷 | snapshot | 특정 시점에 저장한 데이터 상태다. 이후 원천이 바뀌어도 그 시점 결과를 재현하는 데 사용한다. |
| 집계 | aggregation | 일별 행을 월별 합계나 평균처럼 더 큰 시간 단위로 묶는 처리다. |
| 월 기준 | `year_month` | `YYYY-MM` 형식의 월 식별자다. 모델의 입력월, 예측 기준월, 예측 대상월을 구분해서 사용해야 한다. |
| 기준시점 | as-of date | 데이터와 정책이 유효하다고 보는 시점이다. 미래 정보를 과거 예측에 섞지 않기 위해 필요하다. |
| 예측 기준월 | forecast origin | 예측을 만드는 시점에서 마지막으로 관측된 월이다. |
| 예측 대상월 | target month | 실제로 사용량을 예측하려는 다음 월 또는 미래 월이다. |
| 데이터 누수 | data leakage | 예측 시점에는 알 수 없던 미래 값이 학습 특성에 들어가 성능이 과대평가되는 문제다. |

### 0.1.3 물품명 정리와 분류 용어

| 용어 | 설명 |
|---|---|
| 정제 | 공백, 괄호, 특수기호, 운영 접두어처럼 분석을 방해하는 표현을 규칙에 따라 정리하는 단계다. 원본명은 추적을 위해 별도 보존한다. |
| 정규화 | 표기 변형을 일관된 형태로 바꾸는 처리다. 예를 들어 `방)`, `[방문]`을 운영 문맥으로 분리하고 단위 표기를 통일한다. 이 문서의 정규화는 데이터베이스 정규형과 다른 개념이다. |
| 표준화 | 의미가 같은 여러 명칭을 하나의 표준품목과 표준 속성으로 통합하는 처리다. 정규화보다 의미 판정의 비중이 크다. |
| 분류 | 품목을 미리 정한 품목군, family, subtype 등의 범주에 배정하는 처리다. |
| 매핑 | 품목과 약성분, 원자재, 시장지표, HSK처럼 서로 다른 개체 사이에 연결 관계를 만드는 처리다. |
| taxonomy | 분류 체계 | 상위 품목군부터 family·subtype까지 범주와 관계를 정의한 체계다. |
| 품목군 | `item_group_id` | 의약품, 검사시약, 치료재료, 한방약품 등 예측과 운영 정책의 가장 큰 분류 단위다. |
| family | 품목 계열 | 주사기, 카테터, 혈당검사스트립처럼 사용 목적과 형태가 유사한 품목 묶음이다. |
| subtype | 세부유형 | family 안에서 용량·구조·사용대상 등 운영상 재고를 따로 계산해야 하는 세부 유형이다. |
| 규격 | specification/spec | `3 cc`, `22 G`, `15 cm × 200 m`처럼 제품의 크기·용량·치수를 나타낸다. |
| 단위 | unit | 재고를 세는 기준이다. `개`, `병`, `팩`, `Roll` 등이 해당하며 규격과 다르다. |
| 토큰 | token | 물품명에서 분리한 의미 단위다. 제조사, 성분, 용량, 게이지, 포장수량 등을 각각 토큰으로 해석한다. |
| 파싱 | parsing | 물품명 문자열을 토큰과 구조화 컬럼으로 분해하는 과정이다. |
| 제조사 | manufacturer | 제품을 생산하거나 판매하는 회사명이다. 물품의 일반명이나 성분명과 분리한다. |
| 성분 | ingredient | 의약품의 유효성분 또는 제품을 구성하는 물질이다. 제품명과 동일하지 않을 수 있다. |
| 함량 | strength/concentration | 단위 제형 또는 용액에 들어 있는 성분의 양이나 농도다. 예: `500 mg`, `0.9%`. |
| 용량 | capacity/volume | 용기 또는 제품이 담을 수 있는 부피·크기다. 예: `3 cc`, `1 L`. |
| 게이지 | gauge, `G` | 주사침·카테터 등의 굵기 규격이다. `24G`는 24개라는 뜻이 아니다. 일반적으로 G 숫자가 커질수록 외경은 가늘어진다. |
| 포장수량 | pack count | 한 박스·팩 안에 들어 있는 낱개 수다. 제품 규격이나 원장 재고단위와 별도로 저장한다. |
| 제형 | dosage form | 정제, 캡슐, 주사제, 연고처럼 의약품의 투여 형태다. |
| 후보 | candidate | 규칙이나 사전이 제안했지만 아직 확정되지 않은 분류 또는 연결이다. |
| 사전 | dictionary | 검증된 용어, 별칭, 성분, 제조사, 원자재 관계를 재사용하도록 축적한 표다. |
| 충돌 | conflict | 하나의 토큰이나 품목에 서로 양립하기 어려운 해석이 동시에 부여된 상태다. |
| 미분류 | `UNCLASSIFIED` | 근거가 부족해 안전하게 품목군을 확정하지 않은 상태다. 임의 분류보다 검토 대상으로 남기는 것이 목적이다. |
| 예측 가능 | `is_forecastable` | 해당 품목군을 사용량 예측 대상으로 삼을 수 있는지 나타낸다. `NULL`은 아직 정책이 확정되지 않았다는 뜻이다. |

#### 정규화·표준화·분류·매핑의 순서

```text
원본명
→ 정제: 불필요한 표기 분리
→ 정규화: 단위·띄어쓰기·동의표현 통일
→ 속성 파싱: 제조사/성분/용량/게이지/포장수량 분리
→ 표준화: 같은 의미의 품목을 대표품목으로 통합
→ 분류: item_group/family/subtype 부여
→ 매핑: 약성분/원자재/시장지표/HSK 연결
→ 승인 게이트: 근거와 품질을 확인한 연결만 운영 계산에 사용
```

### 0.1.4 재고와 물류 용어

| 용어 | 설명 |
|---|---|
| 기초재고 | opening stock | 기간 시작 시점에 보유한 재고다. |
| 기말재고 | closing/month-end stock | 기간 종료 시점에 원장에 기록된 재고다. |
| 입고 | inbound | 구매, 이관, 반품 등으로 재고가 증가하는 이동이다. |
| 출고 | outbound | 정상사용, 이관, 반품, 폐기 등으로 재고가 감소하는 이동이다. |
| 정상출고 | normal outbound | 환자 진료나 통상 업무로 실제 소비된 수량이며 이 시스템의 기본 수요로 사용한다. |
| 구매입고 | purchase inbound | 외부 구매로 들어온 수량이다. 사용량으로 계산하지 않는다. |
| 이관 | transfer | 기관 또는 부서 사이의 재고 이동이다. 수요와 구분한다. |
| 반품 | return | 공급자나 다른 관리 위치로 되돌리거나 되돌아온 수량이다. 방향에 따라 재고 증감이 달라진다. |
| 폐기 | disposal | 유효기간, 파손 등의 사유로 사용할 수 없어 제거한 수량이다. 정상수요와 구분한다. |
| 자동폐기 | automatic disposal | 시스템 규칙으로 생성된 폐기 성격 컬럼이다. 현재 원장 기대 기말재고 수지식에서는 제외하고 물리 가용량 검사에 별도 활용한다. |
| 원장 수지 | inventory ledger balance | 기초재고와 모든 입출고를 적용했을 때 기대되는 기말재고가 실제 기록과 맞는지 확인하는 계산이다. |
| 물리 가용량 | physical availability | 해당 기간에 실제로 사용할 수 있었던 최대 수량을 추정한 값이다. 비정상 출고나 누락을 탐지하는 데 쓴다. |
| 수요 | demand | 정상 업무에서 필요로 한 수량이다. 현재 구현에서는 음수가 아닌 정상출고량을 기본 수요로 정의한다. |
| 미충족수요 | unmet demand | 필요한 수량 중 재고 부족 때문에 제공하지 못한 부분이다. |
| 결품 | stockout | 수요가 있으나 가용 재고가 없어 제공할 수 없는 상태다. 단순히 원장 재고가 0이라는 사실과 동일하지 않다. |
| 충족량 | served demand | 요청된 수요 중 실제 재고로 제공한 수량이다. |
| 충족률 | fill rate | 전체 요청 수요 가운데 실제 제공한 비율이다. 일반적으로 `충족량 ÷ 요청수요`로 계산한다. |
| 리드타임 | lead time | 주문한 시점부터 사용할 수 있는 재고로 입고될 때까지 걸리는 기간이다. |
| 검토주기 | review period | 재고와 주문 필요성을 다시 검토하는 주기다. |
| 보호기간 | protection period | 현재 주문 정책이 수요를 감당해야 하는 기간으로, 주기검토 정책에서는 보통 `검토주기 + 리드타임`이다. |
| 안전재고 | safety stock | 수요·리드타임 불확실성에 대비해 평균 필요량보다 추가 보유하는 재고다. |
| 기본재고 | base stock | 외부위험을 적용하기 전 보호기간 예상수요와 기본 안전재고를 합친 정책값이다. |
| 목표재고 | target stock | 기본재고에 뉴스·가격·무역 등 외부위험 조정을 반영한 최종 정책 목표다. |
| 재고위치 | inventory position | 현재고에 입고 예정량을 더하고 미처리 주문이나 백오더를 빼서 주문 판단에 사용하는 재고다. |
| 재주문점 | reorder point, ROP | 재고위치가 이 값 이하로 내려가면 주문을 검토하도록 정한 기준이다. |
| 권장 발주량 | recommended order quantity | 목표재고와 재고위치의 차이 중 양수 부분이다. 품질·오래된 데이터·미운영 필터를 통과해야 실제 제안으로 사용한다. |
| 서비스 수준 | service level | 수요 불확실성 속에서 결품 없이 수요를 충족하고자 하는 목표 확률 또는 정책 수준이다. |
| 백오더 | backorder | 수요가 발생했지만 즉시 충족하지 못해 이후 공급해야 하는 미처리 수량이다. |
| 대체품 | substitute item | 기능상 서로 대체할 수 있는 다른 품목이다. 대체품 재고가 충분하면 긴급발주 판단이 달라질 수 있다. |
| 비활성 품목 | inactive item | 최근 사용·입출고가 없어 현재 운영하지 않는 것으로 판단한 품목이다. |
| 오래된 관측 | stale observation | 마지막 실측 시점이 현재 판단 시점보다 지나치게 오래된 상태다. 오래된 현재고로 자동발주하면 안 된다. |

### 0.1.5 예측 모델과 검증 용어

| 용어 | 설명 |
|---|---|
| Module B | 내부 재고 이력과 시계열 특성으로 다음 달 사용량을 예측하는 영역이다. |
| Module C | 뉴스, 원자재 가격, 수출입 위험을 품목에 연결해 수요·공급 위험을 계산하는 영역이다. |
| 모델 | 입력 특성에서 목표값을 추정하도록 학습된 계산 규칙이다. |
| 목표값 | target/label | 모델이 맞히도록 학습하는 정답값이다. 현재 핵심 목표값은 다음 달 정상사용량이다. |
| 특성 | feature | 예측에 사용하는 입력 변수다. 과거 사용량, 이동평균, 월, 품목 속성, 외부위험 등이 해당한다. |
| 시차 특성 | lag feature | 현재보다 이전 시점의 값이다. `lag_1`은 직전 월 값을 뜻한다. |
| 이동 통계 | rolling feature | 최근 일정 기간 값으로 계산한 평균, 표준편차, 합계 등이다. |
| 계절성 | seasonality | 월, 분기, 계절처럼 일정 주기로 반복되는 수요 변화다. |
| 학습 | training | 과거 입력과 정답의 관계를 이용해 모델 파라미터를 정하는 과정이다. |
| 학습 데이터 | train set | 모델 파라미터를 맞추는 데 사용하는 과거 구간이다. |
| 검증 데이터 | validation set | 모델·하이퍼파라미터·앙상블 가중치를 고르는 데 사용하는 이후 구간이다. |
| 테스트 데이터 | test/holdout set | 선택이 끝난 모델의 최종 일반화 성능을 확인하기 위해 마지막까지 분리한 최신 구간이다. |
| 시간 분할 | temporal split | 과거를 학습에, 그보다 최신 기간을 검증·테스트에 사용하는 분할이다. 시계열에서는 무작위 분할보다 적절하다. |
| 백테스트 | backtest | 과거 특정 시점을 예측 기준시점으로 가정해 미래 구간을 예측하고 실제값과 비교하는 검증이다. |
| 기준선 | baseline | 복잡한 모델이 실제로 개선되었는지 비교하기 위한 단순 예측법이다. 직전값, 이동평균 등이 해당한다. |
| LightGBM | Light Gradient Boosting Machine | 여러 결정트리를 순차적으로 결합해 오차를 줄이는 부스팅 모델 구현체다. |
| 결정트리 | decision tree | 특성 조건을 반복적으로 나눠 예측값을 만드는 모델 구성요소다. |
| 부스팅 | boosting | 앞선 모델의 오차를 다음 모델이 보완하도록 약한 모델을 순차 학습하는 방식이다. |
| L1 손실 | absolute error loss | 예측값과 실제값의 절대차를 최소화하는 목적함수다. 큰 이상치의 영향이 제곱오차보다 작다. |
| Tweedie 손실 | Tweedie objective | 0이 많고 양수 값의 꼬리가 긴 사용량 자료에 적합할 수 있는 확률분포 기반 목적함수다. |
| 하이퍼파라미터 | hyperparameter | 트리 수, 학습률, 잎 수처럼 학습 전에 정하는 모델 설정이다. |
| 앙상블 | ensemble | 여러 모델이나 기준선의 예측을 가중 결합해 단일 모델의 약점을 줄이는 방법이다. |
| 앙상블 가중치 | ensemble weight | 각 예측값을 최종 예측에 얼마나 반영할지 정하는 비율이다. 합이 1이 되도록 사용한다. |
| 간헐수요 | intermittent demand | 사용이 없는 기간이 자주 나타나고 간헐적으로 수요가 발생하는 형태다. |
| ADI | Average Demand Interval | 수요가 0보다 큰 관측 사이의 평균 간격이다. 값이 크면 수요 발생이 더 드물다. |
| CV² | squared coefficient of variation | 양수 수요 크기의 변동계수를 제곱한 값이다. 발생량이 얼마나 불규칙한지 나타낸다. |
| 재귀 예측 | recursive forecasting | 한 달 예측 결과를 다음 달 입력으로 다시 사용해 여러 달을 순차 예측하는 방식이다. 오차가 누적될 수 있다. |
| 합성 데이터 | synthetic data | 실측이 아니라 명시한 규칙·분포·가정으로 생성한 데이터다. |
| 시나리오 | scenario | 미래 외부위험, 사용량, 입고 등의 가정을 조합한 계산 조건이다. 실제 미래를 확정하는 예언이 아니다. |

### 0.1.6 성능지표 용어

아래에서 실제값은 \(y_i\), 예측값은 \(\hat{y}_i\), 관측 수는 \(n\)이다.

| 용어 | 수식 | 해석 |
|---|---|---|
| 오차 | \(e_i=\hat{y}_i-y_i\) | 양수면 과대예측, 음수면 과소예측이다. |
| 절대오차 | \(\lvert e_i\rvert\) | 방향을 제거한 예측 차이다. |
| MAE | \(\frac{1}{n}\sum_i\lvert y_i-\hat{y}_i\rvert\) | 한 행당 평균적으로 몇 단위 틀렸는지 나타낸다. |
| RMSE | \(\sqrt{\frac{1}{n}\sum_i(y_i-\hat{y}_i)^2}\) | 큰 오차에 더 큰 벌점을 주는 지표다. |
| WAPE | \(\frac{\sum_i\lvert y_i-\hat{y}_i\rvert}{\sum_i\lvert y_i\rvert}\times100\) | 전체 실제 사용량 대비 총 절대오차 비율이다. 낮을수록 좋다. |
| BIAS | \(\frac{1}{n}\sum_i(\hat{y}_i-y_i)\) | 모델이 평균적으로 과대 또는 과소예측하는 방향을 나타낸다. |
| BIAS_PCT | \(\frac{\sum_i(\hat{y}_i-y_i)}{\sum_i y_i}\times100\) | 전체 실제량 대비 순과대·순과소예측 비율이다. |
| 분류 정확도 | \(\frac{\text{정답 분류 수}}{\text{전체 검증 수}}\) | 정답 라벨이 있는 분류 문제에만 사용하는 비율이다. |
| 정밀도 | precision | 특정 분류라고 예측한 것 중 실제로 그 분류인 비율이다. |
| 재현율 | recall | 실제 특정 분류인 것 중 모델이 찾아낸 비율이다. |
| Spearman 상관 | rank correlation | 두 값의 절대크기보다 순위 관계가 얼마나 일관되는지 `-1~1`로 나타낸다. |

예를 들어 WAPE가 37%라는 것은 전체 실제 사용량의 37%만큼 절대오차가 누적되었다는 뜻이다. 다음을 의미하지는 않는다.

- 품목 분류 정확도가 63%라는 뜻이 아니다.
- 전체 행의 63%를 정확히 맞혔다는 뜻이 아니다.
- 개별 품목의 오차가 모두 37%라는 뜻이 아니다.
- 미래 월말 재고를 63% 확률로 맞힌다는 뜻이 아니다.

### 0.1.7 외부위험과 매핑 용어

| 용어 | 설명 |
|---|---|
| 외부위험 | 내부 사용량 이력만으로 설명되지 않는 감염병, 공급차질, 가격, 무역 등의 외부 신호다. |
| 수요위험 | 질병 유행이나 사건으로 특정 의료용품의 사용량이 증가할 가능성을 나타낸다. |
| 공급위험 | 원자재 가격, 생산 차질, 수입 의존, 특정국 집중으로 조달이 어려워질 가능성을 나타낸다. |
| 이벤트 유형 | 뉴스가 감염병, 생산중단, 수출규제, 물류차질 등 어떤 사건인지 나타내는 분류다. |
| 심각도 | severity | 사건 자체가 재고에 미칠 수 있는 영향의 크기다. |
| 관련도 | relevance | 해당 기사가 대상 질병·품목·원자재와 얼마나 직접적으로 관련되는지 나타낸다. |
| 최신성 | recency | 오래된 기사보다 최근 기사를 더 크게 반영하는 시간 감쇠 요소다. |
| 반감기 | half-life | 뉴스 영향이 절반으로 감소하는 데 걸리는 기간이다. |
| 중복 완화 | novelty/duplicate discount | 같은 사건을 반복 보도한 기사가 점수를 과도하게 늘리지 않도록 기여도를 줄이는 처리다. |
| 노출도 | exposure | 해당 품목이 특정 질병·원자재·국가 위험에 실제로 노출되는 정도다. |
| 원자재 | material | 의료용품 생산에 직접 또는 간접 사용되는 물질이다. 폴리프로필렌, 천연고무, 알루미늄 등이 예다. |
| 시장지표 | market indicator | 원자재 가격 변화를 관찰하기 위해 사용하는 외부 가격 시계열이다. 직접 가격 또는 대체지표일 수 있다. |
| 선물가격 | futures price | 미래 인도 조건으로 거래되는 표준계약의 시장가격이다. 모든 현재 지표가 선물가격인 것은 아니므로 실제 provider 필드를 확인해야 한다. |
| 대체지표 | proxy | 직접 가격이 없을 때 경제적 관련성이 있는 다른 지표로 위험을 근사한 값이다. |
| 전달계수 | transmission weight | 시장지표 변화가 실제 품목 원가·공급위험으로 전달되는 정도를 나타낸다. |
| 대체지표 품질 | proxy quality | 사용한 시장지표가 실제 원자재 가격을 얼마나 잘 대표하는지 나타낸다. |
| 매핑 신뢰도 | mapping confidence | `품목→원자재` 또는 `원자재→지표/HSK` 연결 근거의 확실성이다. |
| HSK | Harmonized System of Korea | 국제 HS 품목분류를 한국 관세 체계에 맞게 세분한 코드다. 수출입 통계를 원자재와 연결할 때 사용한다. |
| 수입의존도 | import dependency | 국내 조달보다 수입에 의존하는 정도를 근사한 위험 요소다. |
| 국가집중도 | country concentration | 수입이 소수 국가에 집중된 정도다. 특정국 문제가 전체 공급에 미치는 영향을 나타낸다. |
| HHI | Herfindahl-Hirschman Index | 국가별 점유율 제곱합으로 계산하는 집중도 지표다. 1에 가까울수록 한 국가에 집중된다. |
| 국가 커버리지 | country coverage | 필요한 교역국 가운데 실제 데이터가 확보된 국가의 비율이다. |
| overlay | 추가 위험 반영층 | 기존 공급위험을 덮어쓰지 않고 무역 위험을 별도 강도로 추가 결합하는 방식이다. |
| 품질 게이트 | quality gate | 데이터·매핑·신뢰도 기준을 통과한 신호만 운영 계산에 반영하는 조건이다. |
| 운영 사용 가능 | operational eligible | 후보 생성이나 연구용 계산을 넘어 실제 정책 계산에 사용할 최소 기준을 통과했다는 뜻이다. |

### 0.1.8 점수·가중치·신뢰도의 차이

이 세 용어는 모두 `0~1` 값으로 표현될 수 있지만 역할이 다르다.

| 구분 | 답하는 질문 | 예 |
|---|---|---|
| 위험점수 | 현재 상황이 얼마나 위험한가? | 원자재 가격 위험 `0.40` |
| 가중치 | 이 위험을 최종 계산에 얼마나 반영할 것인가? | 시장위험 반영 비율 `0.35` |
| 신뢰도 | 입력과 연결을 얼마나 믿을 수 있는가? | 매핑 신뢰도 `0.90` |
| 임곗값 | 어느 값부터 경보 또는 통과로 볼 것인가? | `0.55` 이상이면 WARNING |
| 상한 | 한 요인이 결과를 과도하게 늘리지 못하도록 어디까지 제한할 것인가? | 위험버퍼 최대 `0.75` |

단순 예를 들면 다음과 같다.

```text
관측된 가격위험       = 0.40
시장위험 반영 가중치 = 0.35
매핑 신뢰도          = 0.90
품목 노출도          = 0.80

품목에 전달되는 기여도
= 0.40 × 0.35 × 0.90 × 0.80
= 0.1008
```

즉 위험점수가 `0.40`이라고 해서 목표재고를 바로 40% 올리는 것이 아니다. 연결 강도, 품질, 정책 상한을 순차 적용한다.

### 0.1.9 승인 상태 용어

| 상태 | 의미 |
|---|---|
| 후보 생성 | 규칙·사전·외부검색으로 가능한 연결을 제시한 상태다. |
| identity approved | 품목의 정체성 또는 `품목→원자재` 관계가 승인 기준을 통과한 상태다. |
| market eligible | 승인된 원자재가 사용 가능한 시장지표 경로를 가진 상태다. |
| trade eligible | 승인된 원자재가 유효한 HSK와 수출입 자료 경로를 가진 상태다. |
| operational eligible | 정체성, 외부경로, 품질 기준을 종합해 운영 위험 계산에 사용할 수 있는 상태다. |
| review | 근거가 일부 있으나 사람이 확인해야 하는 상태다. |
| blocked | 필수 근거 부족, 충돌, 품질 실패 등으로 운영 반영을 막은 상태다. |
| API key approved | 외부 제공자가 키 사용을 허용한 상태다. 위 매핑 상태와 독립적이다. |

“모든 후보를 승인한다”는 말은 모든 품목의 모든 외부 위험을 자동 적용한다는 뜻이 아니다. 각 단계에서 유효기간, 매핑 신뢰도, 시장경로, HSK, 국가 커버리지, 데이터 최신성 게이트를 다시 통과해야 한다.

### 0.1.11 수식 기호 읽는 법

| 기호 | 읽는 법과 의미 |
|---|---|
| \(t\) | 시간 인덱스다. 이 문서에서는 주로 월을 뜻한다. |
| \(i\) | 품목 또는 관측 행 인덱스다. |
| \(q_t\) | \(t\)시점의 정상사용량이다. |
| \(\hat{q}_t\) | 모델이 예측한 사용량이다. 기호 위의 `hat`은 예측값을 뜻한다. |
| \(\mu\) | 평균이다. 재고 정책에서는 주로 평균 일사용량을 뜻한다. |
| \(\sigma\) | 표준편차다. 값이 클수록 사용량 변동이 크다. |
| \(L\) | 리드타임이다. 수식 문맥에 따라 일 또는 월 단위를 반드시 확인해야 한다. |
| \(R\) | 검토주기다. |
| \(z\) | 목표 서비스 수준을 안전재고로 바꾸는 표준정규분포 계수다. |
| \(\sum\) | 여러 값을 모두 더한다. |
| \(\prod\) | 여러 값을 모두 곱한다. 독립 위험 결합식에 사용한다. |
| \(\sqrt{x}\) | \(x\)의 제곱근이다. |
| \(\exp(x)\) | 자연상수 \(e\)의 지수함수다. 최신성 감쇠와 포화형 점수에 사용한다. |
| \(\max(a,b)\) | 두 값 중 큰 값을 선택한다. 음수 수요·음수 주문량을 0으로 제한할 때 사용한다. |
| \(\min(a,b)\) | 두 값 중 작은 값을 선택한다. 위험 상한을 적용할 때 사용한다. |
| `clip(x, a, b)` | \(x\)가 \(a\)보다 작으면 \(a\), \(b\)보다 크면 \(b\)로 제한한다. |
| `%` | 백분율이다. `10% = 0.10`이며 계산식 내부에서는 보통 소수로 사용한다. |
| `0~1 점수` | 0은 관측된 위험 없음, 1은 설정한 척도상 최대 위험을 뜻한다. 실제 사건 발생확률과 동일하지 않다. |

## 1. 시스템이 해결하려는 문제

### 1.1 업무 문제

보건기관 재고 데이터에는 다음 문제가 함께 존재한다.

- 같은 물품이 기관별로 다른 이름과 코드로 등록된다.
- `방)혈당스틱`, `혈당스틱`, `[방문]혈당검사스틱`처럼 운영 접두어가 물품명에 섞인다.
- `24G`가 포장 개수가 아니라 바늘 굵기인데 숫자라는 이유로 수량으로 오해될 수 있다.
- 약품은 제품명, 성분, 함량, 제형, 포장수량이 한 문자열에 섞인다.
- 정상 사용, 이관, 반품, 폐기, 자동폐기가 서로 다른 원장 컬럼으로 존재한다.
- 외부 뉴스가 실제로 어느 의료용품의 수요 또는 공급에 영향을 주는지 연결 정보가 필요하다.
- 원자재 가격이나 수출입 위험을 품목에 적용하려면 `품목 → 원자재 → 시장지표/HSK` 경로가 검증되어야 한다.
- 재고가 0이어도 실제 결품, 미운영, 오래된 관측, 원장 누락을 구분해야 한다.

### 1.2 시스템 출력

시스템은 기관·부서·물품 단위로 다음 결과를 만든다.

```text
다음 달 예상 사용량
기본재고량
외부위험 조정 목표재고량
권장 발주량
재고 0 원인
긴급부족 여부
품목군·family·subtype·규격·단위
승인된 원자재·시장지표·HSK 연결
뉴스·가격·무역 위험 점수와 근거
```

### 1.3 현재 범위

- 유일한 재고 학습 원천은 `raw_stock/*.DAT`이다.
- `device/` 폴더와 `MED_DEVICE_5`, `SIDO` 의존성은 사용하지 않는다.
- AI 저장소는 모델·규칙·배치 산출물을 담당한다.
- DB 스키마와 운영 트랜잭션은 백엔드가 담당한다.
- AI 측 DB 도구는 기본 `dry-run`이며, 명시적 기관코드 매핑과 품질검사를 통과해야 DML을 수행한다.
- AI 코드가 운영 DB에 DDL을 직접 실행하지 않는다.

| 재고 상태 | `src/modeling/inventory_status.py` | 실제 결품·미운영·누락·오래된 관측 분류 |
| 미래 시뮬레이션 | `src/modeling/recursive_inventory_simulation.py` | 2026-01~08 재귀 예측 |
| API | `src/serving/api.py` | 사전 계산 산출물 조회와 주문 계산 |
| DB handoff | `src/loading/` | 품질검사된 DML 입력 생성·dry-run 반영 |

### 2.3 정기 배치와 전체 갱신의 차이

`python -m src.main`의 정기 배치는 다음 순서다.

```text
전처리
→ 재고 상태 분류
→ 뉴스 점수
→ 원자재 가격 점수
→ 무역 점수
→ Module C
→ 모델 특성
→ 모델 학습
→ 예측
```

품목 taxonomy 재생성, 과거 가중치 재탐색, 앙상블 재보정은 비용과 검토가 필요한 별도 작업이므로 `src.main`에 자동 포함되지 않는다.

## 3. 데이터 단위와 식별키

### 3.1 데이터 grain

| 단계 | grain |
|---|---|
| 원본 일별 | `재고마감일 × 보건기관코드_en × 부서코드 × 물품코드` |

### 3.2 키의 차이

| 키 | 정의 | 용도 |
|---|---|---|
| `stock_item_key` | `기관::부서::내부물품코드` | 실제 재고와 시계열 예측의 기본키 |
| `local_item_key` | `기관::내부물품코드` | 기관별 물품명 분류와 별칭 연결 |
| `representative_item_id` | 정규화 대표 이름의 해시 기반 ID | 기관별 동일 명칭 후보를 대표품목으로 묶음 |
| `standard_item_key` | 이름 또는 승인된 대표품목 기준 표준키 | 과거와 현재의 의미 연결 |
| `standard_item_definition_key` | 품목군·family·subtype·규격·단위 의미키 | LightGBM 범주 특성 |
| `exact_substitution_group_key` | 기관+family+subtype+규격+단위 | 대체품 재고가 있다고 판단할 수 있는 최소 범위 |

중요한 원칙은 다음과 같다.

- 기관이 다르면 **물리 재고는 절대 자동 합산하지 않는다.**
- 이름이 같아도 기관·부서·코드별 시계열은 유지한다.
- 표준키는 의미 특성과 과거 데이터 연결에 사용한다.
- 대체재고는 승인된 `기관+family+subtype+규격+단위`가 모두 같을 때만 결품 경보 억제에 사용한다.
- family만 같은 재고는 화면 참고용이며 자동 대체로 쓰지 않는다.

## 4. raw_stock 입력과 전처리

### 4.1 파일 형식

- 경로: `raw_stock/*.DAT`
- 인코딩: `UTF-8-SIG`
- 구분자: `|`
- 따옴표: `"`

필수 핵심 컬럼은 다음과 같다.

```text
부서코드
물품코드
물품명
재고마감일
이전최종재고량
마감재고량
입고량
불출입고량
반납입고량
불출출고량
정상출고량
반품출고량
폐기출고량
자동폐기출고량
보정출고량

```

`구입처코드`, `구입단가`는 선택 컬럼이다. 필수 컬럼 누락, 중복 컬럼, 물리적으로 깨진 레코드는 즉시 오류로 처리한다.

### 4.2 현재 데이터 규모

| 구분 | 기간 | 월별 행 | 기관 | 부서 | 물품코드 | 시계열 |
|---|---|---:|---:|---:|---:|---:|
| 현재 | 2024-01~2025-12 | 3,729,983 | 3,530 | 109 | 17,155 | 416,128 |
| 과거 | 2018-01~2019-12 | 1,460,785 | 1,553 | 89 | 11,795 | 179,295 |

### 4.3 수요 정의

모델의 수요는 **정상출고량만** 사용한다.

일별 원장 행 \(t\)의 수요 기여량은 다음과 같다.

```math
q_t = \max(\text{정상출고량}_t, 0)
```

월별 수요는 다음과 같다.

```math
Q_m = \sum_{t \in m} q_t
```

처리 원칙:

- 음수 정상출고는 수요 모멘트에서 0으로 처리한다.
- 해당 행과 관측 기간 자체를 삭제하지는 않는다.
- 이관출고, 반품출고, 폐기출고, 보정출고는 예측 수요에 포함하지 않는다.
- `자동폐기출고량`은 수요와 원장 수지에서 제외하고 별도 감사 컬럼으로 보존한다.

### 4.4 재고 수지식

원장상 기대 마감재고는 다음과 같다.

```math
\hat C_t =
O_t + P_t + T^{in}_t + R^{in}_t
- T^{out}_t - Q_t - R^{out}_t - D_t - A_t
```

| 기호 | 컬럼 |
|---|---|
| \(O_t\) | 이전최종재고량 |
| \(P_t\) | 입고량 |
| \(T^{in}_t\) | 불출입고량 |
| \(R^{in}_t\) | 반납입고량 |
| \(T^{out}_t\) | 불출출고량 |
| \(Q_t\) | 정상출고량 |
| \(R^{out}_t\) | 반품출고량 |
| \(D_t\) | 폐기출고량 |
| \(A_t\) | 보정출고량 |

잔차는 다음과 같다.

```math
\text{ledger residual}_t = C_t - \hat C_t
```

`자동폐기출고량`은 위 식에 넣지 않는다.

### 4.5 데이터 누락 판정용 물리 가용량

정상출고에 실제로 사용할 수 있었던 재고를 다음과 같이 본다.

```math
\text{available}_t =
\max(O_t,0)
+\max(P_t,0)
+\max(T^{in}_t,0)
+\max(R^{in}_t,0)
```

```math
\text{physical violation}_t =
I\left(\max(Q_t,0) > \text{available}_t\right)
```

기존 문서의 좁은 검사인 `정상출고 > 이전재고 + 구매입고`도 감사열로 남기지만, 이관·반납입고를 무시하므로 자동 `DATA_MISSING` 판정에는 사용하지 않는다.

### 4.6 월별 집계

월별로 다음과 같이 집계한다.

| 값 | 집계 |
|---|---|
| 월초재고 | 해당 월 첫 `opening_stock` |
| 월말재고 | 해당 월 마지막 `closing_stock` |
| 월간 사용량 | 정상출고량 합 |
| 월간 입고 | 구매+이관+반납 입고 합 |
| 기타 출고 | 이관+반품+폐기+보정 출고 합 |
| 평균재고 | 유효 마감재고 관측 평균 |
| 결품률 | `마감재고=0` 관측 수 / 유효 재고 관측 수 |

현재 월별 원장에서 발견된 수지 잔차 위반은 8개 행이다. 이 값은 모델 정확도가 아니라 원장 품질지표다.

## 5. 품목명 표준화와 분류

### 5.1 표준화가 필요한 이유

다음 세 이름은 운영 태그만 다르고 같은 혈당검사 스트립 후보일 수 있다.

```text
방)혈당스틱
혈당스틱
[방문]혈당검사스틱
```

반면 다음 숫자는 서로 다른 역할을 가진다.

```text
3cc        → 주사기 용량
24G        → 바늘 외경을 나타내는 gauge
24mm       → 바늘 길이
100개입    → 포장 수량
500mg      → 약 성분 함량 후보
10cm*10cm  → 제품 치수
```

숫자만 추출해 모두 “수량”으로 보면 원자재 매칭, 단위 집계, 사용량 예측이 모두 잘못된다.

### 5.2 표준화 단계

```text
원시 물품명
→ 공백·개행 정리
→ 운영 접두어/태그 분리
→ 제품명과 괄호·규격 토큰 분리
→ 제조사·성분·제형·용량·함량·게이지·길이·치수·포장수량 추출
→ 기관별 별칭 생성
→ 동일 대표품목 후보 생성
→ 품목군/family/subtype/spec/unit 후보
→ 공식·공공·검증 사전 근거 연결
→ 승인 taxonomy 또는 검토 큐
```

### 5.3 파싱 속성

| 속성 | 예시 | 의미 |
|---|---|---|
| 운영 태그 | `방)`, `[방문]` | 사용 부서·업무 표식이며 제품 본체에서 분리 |
| 제조사 후보 | `(주)OO`, `OO제약` | 제조사 또는 공급사 후보 |
| 성분 | 아세트아미노펜, 염화나트륨 | 약품 원료 연결의 중심 |
| 제형 | 정, 캡슐, 주사, 연고, 패치 | 의약품 subtype |
| 용량 | 3cc, 500mL, 5L | 제품 또는 용기의 용량 |
| 함량 | 500mg, 0.9% | 활성성분 강도 또는 농도 |
| 게이지 | 22G, 24G | 바늘 굵기이며 수량이 아님 |
| 길이 | 24mm | 바늘·카테터 길이 |
| 치수 | 10cm x 10cm | 거즈·포장재 등의 규격 |
| 포장수량 | 100개입, 10매 | 한 포장 안의 개수 |
| 재고단위 | EA, ROLL, SHEET 등 | 서로 다른 단위를 합산하지 않기 위한 기준 |

현재 속성 파서 결과:

| 항목 | 대표품목 수 |
|---|---:|
| 전체 대표품목 | 101,546 |
| gauge 추출 | 1,008 |
| 용량 추출 | 6,563 |
| 포장수량 추출 | 16,494 |
| 성분 추출 | 8,140 |
| 농도 추출 | 4,361 |
| gauge와 약 함량 위치 충돌 | 0 |
| 투여기준과 포장수량 위치 충돌 | 0 |

이 수치는 파싱 커버리지이며 사람 정답과 비교한 정확도가 아니다.

- 실제 재고와 사용량은 기관별로 분리한다.
- 기관별 가격, 공급처, 재고위치는 합치지 않는다.
- 표준화는 “의미 공유”이고 물리 재고 병합은 아니다.

### 5.8 독립 분류 정확도의 한계

현재 사람 라벨로 만든 독립 gold set이 없으므로 품목 분류에 대해 “정확도 95%” 같은 값을 제시할 수 없다.

현재 가능한 평가는 다음과 같다.

- 기존 동결 승인 1,177건과의 회귀 일치율: 100%
- 단, 동일 규칙 계열 산출물이므로 독립 정확도가 아니라 안정성 검사다.
- 기존 정규화 파일과 local item 연결 커버리지: 409,519/409,519
- 해당 참조에도 규칙 기반 pseudo-label이 있어 사람 정답으로 간주할 수 없다.

발표에서는 “행 보존·키 유일성·토큰 충돌 0·승인 회귀 안정성은 검증했으나 독립 정답셋 정밀도는 아직 없다”고 설명해야 한다.

## 6. 2018~2019 데이터와 현재 데이터 연결

### 6.1 단순 연결이 위험한 이유

2019년 이후 2024년까지 데이터가 없다. 동일 로컬 코드라도 시간 공백을 넘어 lag를 이어 붙이면 2019년 12월이 2024년 1월의 직전 달처럼 처리되는 오류가 생긴다.

### 6.2 연결 정책

- 2018~2019 local item은 현재 대표품목과 strict name, strict semantic, 유일한 core name으로 연결한다.
- 현재 표준품목으로 안전하게 연결되지 않은 과거 전용 이름은 보관하되 학습에서 제외한다.
- 2019→2024 공백에서 새 `series_segment_id`를 시작한다.
- 표준품목 의미 특성은 공유하지만, 기관·부서·물품코드별 물리 시계열은 분리한다.

### 7.4 원자재에서 시장지표로 가는 경로

각 경로의 가중치는 다음 곱이다.

```math
w^{market}_{path}
= w_{transmission}
\times q_{proxy}
\times w_{mapping}
\times e_{exposure}
\times c_{mapping}
```

| 요소 | 의미 |
|---|---|
| `transmission_weight` | 시장가격 변화가 원자재에 전달되는 정도 |
| `proxy_quality` | 직접지표가 아닌 대리지표의 품질 |
| `mapping_weight` | 품목-원자재 연결 강도 |
| `exposure_score` | 해당 품목이 원자재에 노출된 정도 |
| `mapping_confidence_score` | 매핑 근거 신뢰도 |

경로별 위험 기여:

```math
r_{path}=r_{market\ factor}\times w^{market}_{path}
```

여러 경로는 단순합 대신 다음 식으로 결합한다.

```math
r_{commodity}=1-\prod_p(1-r_{path,p})
```

이 식은 여러 위험을 누적하면서도 결과를 0~1 범위에 유지한다.

### 7.5 HSK 연결

- 기준 파일: `관세청_HS부호_20260101.xlsx`
- 정규화 HSK 항목: 12,469
- 승인 원자재-HSK 경로: 32
- 승인 원자재 코드: 28
- HSK는 10자리, 유효기간, 공식 명칭, direct/proxy 여부를 검증한다.

HSK 경로 가중치:

```math
w^{trade}_{path}
=w_{item\to material}
\times e_{exposure}
\times c_{mapping}
\times w_{material\to HSK}
\times q_{HSK\ proxy}
```

품목별 무역 위험:

```math
r_{item,trade}=1-\prod_p(1-r_{HSK,p}\times w^{trade}_{path,p})
```

문자형 매핑 신뢰도는 다음과 같이 수치화한다.

| mapping confidence | 점수 |
|---|---:|
| verified | 1.00 |
| high | 0.90 |
| medium | 0.65 |
| low | 0.35 |
| 미확인 문자열 | 0.50 |

### 10.2 가격 특징

#### 30일 수익률

```math
return_{30}=\frac{P_t}{P_{asof(t-30)}}-1
```

과거 기준값은 30일 이전에서 가장 가까운 관측을 사용하되 실제 간격이 30~60일인 경우만 유효하다.

#### 30일 변동성

```math
vol_{30}=std(r_{obs}, 30D)\times\sqrt{30}
```

관측이 적으면 최근 3개 관측 수익률 표준편차를 보조값으로 사용한다.

#### 90일 평균 대비 가격

```math
level_{90}=\frac{P_t}{mean(P,90D)}-1
```

### 10.3 0~1 위험 정규화

```math
r_{return}=clip\left(\frac{\max(return_{30},0)}{0.20},0,1\right)
```

```math
r_{vol}=clip\left(\frac{\max(vol_{30},0)}{0.12},0,1\right)
```

```math
r_{level}=clip\left(\frac{\max(level_{90},0)}{0.15},0,1\right)
```

시장요인 위험:

```math
r_{factor}
=0.45r_{return}+0.30r_{vol}+0.25r_{level}
```

가격 하락은 현재 공급위험 상향에 사용하지 않고 0으로 절삭한다. 이는 가격 급등·변동성·고가격 상태를 공급압력으로 해석하는 단방향 정책이다.

## 14. 예측 평가

### 14.1 지표 수식

실제값 \(y_i\), 예측값 \(\hat y_i\), 오차 \(e_i=y_i-\hat y_i\)라 한다.

```math
MAE=\frac{1}{N}\sum_i|e_i|
```

```math
RMSE=\sqrt{\frac{1}{N}\sum_i e_i^2}
```

```math
RMSLE=
\sqrt{\frac{1}{N}\sum_i
\left(\ln(1+\max(y_i,0))-\ln(1+\max(\hat y_i,0))\right)^2}
```

0이 아닌 실제값에 대해서만:

```math
MAPE=
\frac{100}{N_{y\ne0}}
\sum_{i:y_i\ne0}\frac{|e_i|}{|y_i|}
```

```math
SMAPE=
\frac{100}{N_*}
\sum_i\frac{2|e_i|}{|y_i|+|\hat y_i|}
```

```math
WAPE=
100\times\frac{\sum_i|e_i|}{\sum_i|y_i|}
```

```math
BIAS=\frac{1}{N}\sum_i(\hat y_i-y_i)
```

```math
BIAS\_PCT=
100\times\frac{\sum_i(\hat y_i-y_i)}{\sum_i|y_i|}
```

## 15. 재고 0 원인과 긴급부족

### 15.1 일평균과 일표준편차

시계열 최초 관측일부터 최신 데이터 날짜까지의 달력 일수를 \(T\)라 한다. 관측이 없는 날은 수요 0으로 본다.

```math
\mu=\frac{\sum_t q_t}{T}
```

```math
E[q^2]=\frac{\sum_t q_t^2}{T}
```

```math
\sigma=\sqrt{\max(E[q^2]-\mu^2,0)}
```

현재 \(\mu\)와 \(\sigma\)의 하한은 모두 0이다. 과거처럼 모든 품목에 임의의 0.01 또는 0.1 하한을 주지 않는다.

최근 3개월 보조 평균:

```math
\mu_{forecast,3m}=
\frac{최근\ 3개월\ 정상출고합}{92}
```

### 15.2 원인 규칙

| 조건 | `zero_stock_reason` |
|---|---|
| 최신 관측이 2025-12보다 이전이거나 현재고 누락 | `STALE_OR_MISSING_OBSERVATION` |
| 현재고 <= 0, 전 기간 정상출고 0 | `NOT_OPERATED` |

## 16. 목표재고와 권장발주량

현재 코드에는 목적이 다른 두 재고정책이 있다.

1. 월별 예측과 Module C를 결합하는 **주기검토 목표재고 정책**
2. 일수요 표준편차와 공급위험 레벨을 쓰는 **연속검토 SS/ROP 정책**

둘을 하나의 공식으로 혼합하지 않았으며, 최종 운영 기준은 백엔드·업무팀과 결정해야 한다.

### 16.1 주기검토 기본재고

| 기호 | 의미 | 현재 기본값 |
|---|---|---:|
| \(\hat U\) | 월 예측 사용량 | 모델 출력 |
| \(R\) | 검토주기 | 30일 |
| \(L\) | 조달 리드타임 | 입력 없으면 15일 |
| \(s_0\) | 기본 안전재고율 | 0.20 |

보호기간:

```math
P=R+L
```

보호기간 수요:

```math
D_P=\hat U\times\frac{P}{30}
```

기본 안전재고:

```math
SS_0=D_P\times0.20
```

기본재고:

```math
B=D_P+SS_0
```

### 16.2 Module C 수요 조정

수요 위험 \(r_d\):

```math
u_d=r_d\times0.35
```

```math
\hat U_{risk}=\hat U(1+u_d)
```

단, Module C 신호가 이미 예측모델에 포함된 경우:

```math
u_d=0
```

이중계상을 막기 위한 규칙이다.

현재 최종 앙상블의 전역 설정에 Module C 가중치 0.60이 있으므로 `external_demand_signal_in_forecast=true`가 전체 예측 행에 기록되고 정책단 수요 uplift는 억제된다. 다만 현재 플래그는 패턴별 실제 Module C 가중치가 아니라 전역 fallback 가중치를 기준으로 한다. 향후 2024~2025 뉴스가 보강되어 수요위험이 양수가 되면, `all_zero`나 `insufficient_history`처럼 패턴 가중치에서 Module C가 0인 행은 행별 포함 여부로 판정하도록 개선해야 한다.

### 16.3 Module C 공급 조정

공급 위험 \(r_s\):

```math
L_{eff}
=L(1+0.50r_s)+14r_s
```

```math
P_{risk}=R+L_{eff}
```

```math
D_{risk}
=\hat U_{risk}\times\frac{P_{risk}}{30}
```

동적 안전재고율:

```math
s_{risk}=0.20+0.25r_s
```

```math
SS_{risk}=D_{risk}\times s_{risk}
```

제약 전 목표재고:

```math
T^*=D_{risk}+SS_{risk}
```

### 16.4 위험버퍼 상한

```math
buffer_{raw}=\max(T^*-B,0)
```

```math
buffer_{cap}=D_P\times0.75
```

```math
buffer=\min(buffer_{raw},buffer_{cap})
```

```math
target\_stock=B+buffer
```

수요·공급 buffer의 상세 기여도도 같은 비율로 축소해 합계가 상한을 넘지 않게 한다.

### 16.5 재고위치와 발주량

```math
inventory\_position
=current\_stock+on\_order-backorder
```

```math
recommended\_order
=\max(target\_stock-inventory\_position,0)
```

발주 억제:

| 상태 | 처리 |
|---|---|
| `DORMANT` | 0 |
| `NOT_OPERATED` | 0 |
| `DATA_MISSING` | 계산값을 제공하지 않음, `NaN` |
| `STALE_OR_MISSING_OBSERVATION` | 계산값을 제공하지 않음, `NaN` |

### 16.6 Module C 컬럼이 없는 이전 형식의 fallback

이전 산출물을 읽어 Module C 전용 컬럼이 없을 때는 호환성 정책을 사용한다.

```math
r_{material}=\max(r_{material\ news},r_{commodity})
```

```math
r_{external}
=0.4r_{demand}+0.3r_{supply}+0.3r_{material}
```

보호기간 수요 \(D_P\)에 대해:

```math
buffer_d=D_P\times r_d\times0.20
```

```math
buffer_s=D_P\times r_s\times0.20
```

```math
buffer_m=D_P\times r_m\times0.10
```

```math
buffer=
\min(buffer_d+buffer_s+buffer_m,\ D_P\times0.50)
```

현재 정규 배치에는 Module C 컬럼이 존재하므로 운영 계산은 앞 절의 v1.4 정책을 사용한다. 이 fallback은 과거 파일·API 호환을 위한 코드 경로다.

## 17. 별도 SS/ROP 공급위험 레벨 정책

### 17.1 공급위험 기준레벨

고정 구조 위험과 월별 이벤트 위험을 분리한다.

```text
baseline_supply_risk_level
  = 원자재 위험 메타코드로 결정되는 고정 구조

module_c_event_supply_risk_level
  = 뉴스·가격·수출입으로 월별 변하는 사건 위험
```

| 레벨 | z | 리드타임 배수 |
|---|---:|---:|
| NORMAL | 1.28 | 1.00 |
| CAUTION | 1.65 | 1.10 |
| WARNING | 2.05 | 1.25 |
| CRITICAL | 2.33 | 1.50 |

현재 고정 메타코드 규칙:

| 공급위험 메타코드 | 축 | 기준레벨 | 해석 |
|---|---|---|---|
| `GENERAL_LOW_RISK` | supply | NORMAL | 특이 공급취약 근거 없음 |
| `SINGLE_USE_HIGH_TURNOVER` | supply | NORMAL | 고회전 자체는 공급취약 근거가 아님 |
| `BASIC_INFUSION_HIGH_VOLUME` | supply | CAUTION | 대량수요와 공급집중 가능성 |
| `COMMODITY_PRICE_VOLATILE` | supply | CAUTION | 가격변동 노출 |
| `COLD_CHAIN_DEPENDENT` | supply | CAUTION | 온도유지 물류 제약 |
| `PROPRIETARY_DEVICE_LOCKIN` | supply | WARNING | 전용기기 호환 잠김 |
| `GENERIC_API_IMPORT_DEPENDENCY` | supply | WARNING | 제네릭 원료 수입의존 |
| `ANTIBIOTIC_API_IMPORT` | supply | WARNING | 항생제 원료 수입의존 |
| `PANDEMIC_SURGE_SENSITIVE` | demand | NORMAL | 수요축이므로 고정 공급레벨에서 제외 |
| `NOT_APPLICABLE` | none | NORMAL | 정책 비대상 |

여러 공급코드가 있으면 rank가 가장 높은 기준레벨을 선택한다. 동적 사건코드와 수요코드는 고정 공급레벨 계산에서 제외하며, 알 수 없는 코드는 NORMAL로 두되 `needs_review=true`를 기록한다.

CRITICAL은 다음 세 조건과 승인 상태가 모두 있어야 강제 승격할 수 있다.

```text
국가필수품목
단일 수입원
대체 불가
critical override review_status=approved
```

### 17.2 연속검토 수식

일평균 \(\mu\), 일표준편차 \(\sigma\), 기준 리드타임 \(L\), 레벨별 배수 \(m\), z값 \(z\):

```math
L_{eff}=L\times m
```

```math
SS=z\sigma\sqrt{L_{eff}}
```

```math
ROP=\mu L_{eff}+SS
```

현재 target cover 1일:

```math
target=\mu(L_{eff}+1)+SS
```

```math
order=\max(target-on\_hand,0)
```

상태:

| 조건 | 상태 |
|---|---|
| on hand <= 0 | CRITICAL |
| on hand < ROP | BELOW_ROP |
| on hand < 1.2 × ROP | WATCH |
| 그 외 | OK |

### 17.3 계산 예시

```text
mu=4개/일
sigma=2개/√일
원천 리드타임=10일
WARNING: z=2.05, 배수=1.25
현재고=40개
```

```math
L_{eff}=10\times1.25=12.5
```

```math
SS=2.05\times2\times\sqrt{12.5}\approx14.50
```

```math
ROP=4\times12.5+14.50\approx64.50
```

```math
target=4\times13.5+14.50\approx68.50
```

```math
order=68.50-40=28.50
```

현재고가 ROP보다 작으므로 상태는 `BELOW_ROP`이다.

### 17.4 두 정책이 아직 공존하는 이유

| 정책 | 장점 | 현재 제한 |
|---|---|---|
| 월별 보호기간+Module C | 예측 사용량과 외부위험을 직접 반영 | 안전재고가 고정 비율 기반, 품목 리드타임 연결 부족 |
| 일별 SS/ROP | 수요 변동성과 서비스수준 z를 명시 | 월별 외부위험·검토주기와 최종 통합 기준 미확정 |

최종 운영 공식은 다음 중 하나로 결정해야 한다.

1. 주기검토 정책을 정본으로 하고 z 기반 SS를 내부 안전재고로 교체
2. 연속검토 ROP를 정본으로 하고 Module C를 z 또는 리드타임에 반영
3. 품목군별로 정책을 분리

현재 로컬 DB handoff는 이 결정 전까지 기존 backend SS/ROP/발주 컬럼을 보호한다.

## 18. 2026년 1~8월 재귀 시뮬레이션

### 18.1 목적

실제 2026년 1~8월 원장이 없지만 2026년 8월 재고량 시나리오가 필요해 다음 과정을 만들었다.

```text
2025-12 관측 상태
→ 2026-01 사용량 예측
→ ±10% 가상 요청량
→ 발주 입고·소비·월말재고 계산
→ 계산된 소비와 월말재고를 다음 달 lag로 전달
→ 2026-08까지 반복
```

### 18.2 가상 사용량

품목·월 키와 seed 42를 사용한 결정론적 삼각분포:

```math
f_{i,m}\sim Triangular(0.9,1.0,1.1)
```

```math
virtual\_requested_{i,m}
=predicted\_usage_{i,m}\times f_{i,m}
```

같은 seed와 키를 사용하면 재실행해도 같은 값이 나온다.

### 18.3 재고 흐름

```math
available_{i,m}
=opening_{i,m}+inbound_{i,m}
```

```math
served_{i,m}
=\min(virtual\_requested_{i,m},available_{i,m})
```

```math
unmet_{i,m}
=virtual\_requested_{i,m}-served_{i,m}
```

```math
ending_{i,m}
=opening_{i,m}+inbound_{i,m}-served_{i,m}
```

```math
opening_{i,m+1}=ending_{i,m}
```

다음 달 수요 lag에는 요청량이 아니라 실제 충족된 `served`를 넣는다. 재고가 부족했던 달의 미충족 수요는 다음 달 학습 상태에 자동 이월되지 않으므로, 이 시뮬레이션은 잠재수요가 검열되는 보수적 경로를 갖는다.

```text
2025-12 Module C 위험을 미래에 고정
2025-12 재고 상태를 미래에 고정
미래 폐기량 0
미래 자동폐기 조정량 0
backorder 0
실제 발주 리드타임 없음
```

## 25. 예상 질문과 답변

### Q1. LightGBM이 최종 재고량을 예측하나요?

아니다. LightGBM은 다음 달 정상 사용량을 예측한다. 최종 재고량은 리드타임·검토주기·안전재고·외부위험을 반영한 정책 계산이며, 미래 월말재고는 별도 재고 흐름 시뮬레이션 결과다.

### Q2. 품목 분류 정확도는 얼마인가요?

독립 사람 정답셋이 없어 정확도 수치를 주장할 수 없다. 현재는 행 보존, 키 유일성, 기존 승인 회귀 일치, 토큰 충돌 검사까지 완료했다. 다음 단계는 품목군별 사람 검수 gold set이다.

### Q3. WAPE 37%면 성능이 낮은 것 아닌가요?

전체 행의 약 24%가 실제 사용량 0이고 간헐·lumpy 수요가 많다. 단순 기준선 3개월 평균 WAPE 44.52%, 직전 달 48.07%보다 낮고, 최종 홀드아웃에서 기존 L1보다 WAPE와 RMSE, bias가 모두 개선되었다. 다만 운영 비용 기준 검증은 추가로 필요하다.

### Q4. 왜 2018~2019를 쓰나요?

현재 품목과 strict/core 규칙으로 안전하게 연결된 행만 사용했고, 2025 검증에서 WAPE가 0.81%p 개선되었다. 2019→2024 공백은 lag를 끊어 시간상 인접한 것처럼 처리하지 않는다.

### Q5. 모든 원자재를 승인했다면 위험을 전부 적용하나요?

아니다. bulk approval은 후보 수용이다. 정체성, 뉴스, 시장가격, 운영 재고조정의 eligibility가 따로 있으며, 제품별 외부 사실과 운영 품질 게이트가 부족한 행은 자동발주에 쓰지 않는다.

### Q6. 무역 가중치의 근거는 무엇인가요?

20개국×32 HSK 완결 캐시에서 10개 위험요소를 만들고, 시간순 train/validation/test를 분리해 다음 달 결품 proxy의 weighted MAE와 Spearman을 비교했다. test weighted MAE는 기존보다 약 0.91% 개선됐지만 인과효과는 아니다.

### Q7. 뉴스는 실제 모델 성능을 높였나요?

현재 수집 뉴스가 2026-07뿐이라 2024~2025 학습 구간에서 뉴스 전용 모델을 검증하지 못했다. 뉴스 B/C 모델은 0 특성 때문에 자동 제외됐다. 현재 검증된 외부효과는 주로 가격·무역 Module C 경로다.

### Q8. 2026년 8월 재고 274,209,471은 믿을 수 있나요?

실제 관측치가 아니라 합성 시나리오다. 특히 21개 대형 원천재고가 총합의 대부분을 차지해, 이를 분리한 비교 집계는 54,295,186이다. 실제 2026년 입고·폐기·리드타임이 들어오면 다시 계산해야 한다.

### Q9. 현재 바로 자동발주할 수 있나요?

광범위한 자동발주는 아직 안 된다. 최신 실제 데이터가 2025-12라 현재 예측은 stale이고, Module C 품질 게이트도 batch release를 허용하지 않는다. API도 stale 예측의 주문 계산을 차단한다.

### Q10. 가장 중요한 다음 작업은 무엇인가요?

2026 실제 원장과 실제 발주-입고 리드타임을 연결하는 것이다. 그다음 분류 gold set, 뉴스 과거자료, 재고정책 정본, 비용 기반 최적화 순서가 적절하다.

## 29. 최종 요약

WeP-Stock AI는 다음 네 계층을 분리한 시스템이다.

```text
1. 관측 계층
   raw_stock 원장, 사용량, 현재고, 품질 위반

2. 의미 계층
   품목군, family, subtype, 규격, 단위, 성분, 원자재, HSK

3. 예측·위험 계층
   LightGBM 사용량 예측, 뉴스·가격·무역 Module C

4. 정책 계층
   안전재고, 목표재고, 발주량, 결품 경보, 미래 시뮬레이션
```

현재 가장 강한 성과는 다음이다.

- 2018~2019와 현재 데이터를 물리 시계열을 훼손하지 않고 연결했다.
- 24G 같은 규격과 포장 개수를 분리하는 속성 파서를 구축했다.
- LightGBM 단일 모델보다 수요패턴별 앙상블이 WAPE, RMSE, bias를 함께 개선했다.
- 뉴스·가격·무역이 아무 품목에나 전파되지 않도록 승인 경로를 만들었다.
- 재고 0을 무조건 결품으로 보지 않고 최종 긴급부족 770개로 좁혔다.
- 2026년 실제 데이터가 없다는 사실을 숨기지 않고, 가정이 명시된 재귀 시뮬레이션으로 8월 시나리오를 만들었다.

현재 가장 큰 제약은 최신 실제 데이터와 실제 조달 리드타임의 부재다. 따라서 중간 발표의 결론은 “완전 자동발주가 끝났다”가 아니라 다음과 같이 잡는 것이 정확하다.

> 원본 재고를 표준화하고 사용량·외부위험·재고정책을 분리 계산하는 전체 파이프라인을 구축했으며, 시간분할 백테스트에서 예측 성능 개선을 확인했다. 다음 단계는 2026년 실제 데이터, 실제 리드타임, 독립 분류 정답셋으로 운영 성능을 검증하는 것이다.
