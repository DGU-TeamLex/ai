# 큰 오차를 줄이기 위한 후속 실험

기존 입력 변수 확장 실험의 코드를 별도 브랜치에 가져와 수정했다. 실행 중인 기존 작업과 서비스 모델은 변경하지 않는다. 이 문서는 앞선 입력 변수 확장 실험 안내보다 이 브랜치의 실행 조건에 우선한다.

## 바꾸는 내용과 비교 조건

51개 변수 기준, 사용 패턴 변수 추가, 사용 패턴과 변동 폭 변수 추가, 마지막 조건에서 최대 학습 횟수만 4,000회로 늘린 모델을 비교한다. 나머지는 최대 1,999회다. 100회 동안 검증 오차가 개선되지 않으면 조기 종료한다. 전체 학습 자료를 사용하며 표본을 줄이지 않는다.

추가 변수는 최근 6개월 사용량의 최대치·중앙값·범위·변동계수, 현재 관측 사용량/그 이전 3개월 평균, 현재 관측이 이전 6개월 최대치를 넘는지, 관측 개월 수, 6개월 및 12개월 전 사용량의 결측 표시 등 9개다. 예측 대상 월이 아니라 예측 시점까지 확인한 자료만 사용한다. 월이 누락되거나 음수·미관측 사용량이 있으면 과거 기록 연결을 끊는다. 분모가 0이면 비율은 결측으로 남기며 학습 구간에서 계산한 중앙값으로 대체한다.

이는 큰 오차가 나는 미래 행을 미리 식별하거나 제외하는 방법이 아니다. 과거에 변동이 컸는지 모델이 구분할 정보를 제공하는 실험이다. 실제 일별 사용일 수나 거래 빈도는 원본 상세 자료를 확인하지 않았으므로 이번 실험에 포함하지 않는다.

두 검증 구간은 2025년 5~6월과 8~9월이다. 절대오차 합을 실제 사용량 합으로 나눈 WAPE로 후보를 선택하고 선택 파일을 먼저 저장한다. 그 뒤 10~12월에서 재학습 기준 모델과 선택 모델의 WAPE·BIAS를 계산한다. 학습 횟수의 효과는 behavior_tail과 behavior_tail_long을 비교해야 한다. 기존 모델의 예측값과 재학습 기준 모델은 별도로 비교한다.

이미 확인한 평가 자료에서 얻은 진단이 후속 연구 방향에 영향을 주었다. 따라서 검증 구간에서 후보를 선택하더라도 10~12월 결과를 완전히 새로운 독립 검증이나 확증적 통계 검정으로 주장하지 않는다. 향후 새로운 기간 자료가 필요하다. WAPE 개선이 BIAS나 품절 개선을 보장하지 않으며 서비스 모델을 자동 교체하지 않는다.

## 실행과 보호

scripts/wait_then_tail_experiment.py가 앞선 outputs/feature_expansion_v1/status.json의 정상 완료와 결과 파일을 확인하고, feature_expansion_experiment.py 프로세스가 모두 종료됐으며 사용 가능 RAM이 4 GiB 이상일 때만 시작한다. 대기는 최대 12시간이며 이전 실패·일시정지 상태에서는 실행하지 않는다. 출력 경로별 독점 queue.lock으로 중복 예약을 막는다. 재실행은 자동으로 하지 않는다.

CPU 스레드 2개, 순차 학습을 유지한다. 작업별 2시간 제한과 가용 RAM 1.5 GiB 미만 중단을 적용한다. 각 모델이 끝날 때 저장한다. 이 보호 장치가 전원·발열·하드웨어 문제까지 방지하는 것은 아니다. 강제 종료가 재발하면 추가 실행 전에 원인을 점검해야 한다.

산출물은 outputs/tail_features_v1 아래의 status.json, 모델별 JSON/pkl, selection.json, test_results.json, 결과요약.md다. 큐의 대기·오류 기록은 outputs/tail_queue.stdout.log와 outputs/tail_queue.stderr.log에 남긴다.
