# 실제 출고 기록과 예측 오차 점검

## 결론

예측값을 잘못된 월에 연결했거나 이동·반품을 사용량에 더했기 때문에 WAPE가 35%라는 근거는 이번 점검에서 나오지 않았다. 평가 대상 359,335건의 실제값은 월별 정상출고 양수 합계와 모두 일치했다. 원본 DAT 10개, 16,265,602개 기록을 순차 조회해 추출한 큰 오차 20건과 비교 사례 7건도 원본 합계와 모두 일치했다.

다만 일부 대량 사용 품목에서 모델이 이미 확인된 사용 규모보다 크게 낮게 예측했다. 반대로 이런 극단적인 사례만 고쳐도 전체 WAPE가 크게 떨어진다고 보기는 어렵다. 대부분의 오차가 발생하는 중간 사용 규모에서도 개선이 필요하다. 일별 기록을 이용한 빈도·최근 활동량 정보와 규모에 따른 예측 보정이 다음 검증 대상이다.

## 무엇을 점검했는가

대상 모델은 첫 입력 변수 실험에서 두 검증 기간의 합산 WAPE로 선택된 사용 패턴 추가 LightGBM이다. 2025년 10~12월 359,335건의 WAPE는 35.4345%, BIAS는 -7.7829%다. 이 기간은 이미 여러 번 확인한 평가 자료다. 이번 분석은 원인 후보를 찾는 사후 점검이며 독립 성능 검증이나 인과관계 증명이 아니다.

1. 예측 대상 월과 같은 월의 월별 집계를 기관·부서·품목·월로 1:1 연결했다. 미연결·중복 연결이면 중단한다.
2. 예측에 사용한 과거 정보는 예측 시점 월로 따로 연결했다. 평가 대상 월의 품질 정보는 원인 점검용이며 입력 변수로 넣지 않았다.
3. 큰 오차 순으로 서로 다른 20개 품목 시계열을 선택했다. 같은 평가 월·기록 단위·실제 수량의 자릿수 구간에서 상위 5% 오차를 제외한 중간 오차 사례를 찾아 비교했다. 조건을 만족하는 중복 없는 비교 사례는 7개였다. 20:20 짝 비교가 아니며 대표 표본도 아니다.
4. 원본 파일을 20,000행씩 읽어 선택 사례의 예측 시점 월과 대상 월 기록만 추출했다. 원본 전체를 수정하거나 모델을 재학습하지 않았다.

## 실제값을 만드는 공식

현재 예측 대상은 해당 월 기록마다 정상출고량의 음수를 0으로 처리한 뒤 더한 값이다.

`월별 예측 대상 = Σ max(각 기록의 정상출고량, 0)`

부서 이동, 반품, 폐기, 자동폐기, 보정출고는 이 식에 더하지 않는다. 음수 정상출고는 별도 열에 보존한다. 이는 코드에서 확인한 처리 방식이지, 정상출고가 실제 환자 사용량과 완전히 같다는 의미는 아니다. 기록 업무와 실제 소비의 관계는 여전히 확인이 필요하다.

예측 대상과 월별 양수 합계의 불일치는 0건이었다. 저장된 부동소수점 정밀도를 고려해 상대 허용오차 0.00001, 절대 허용오차 0.0001로 비교했다.

## 기록 문제와 오차의 관계

- 음수 정상출고가 있었던 평가 월은 1건이었다. 전체 오차 기여는 약 0.00007%로, 이번 평가의 주된 원인이 아니다.
- 이동 기록이 있는 월은 290건, 전체 오차 기여는 0.0051%였다.
- 반납·반품 기록이 있는 월은 493건, 전체 오차 기여는 0.0931%였다.
- 보정출고가 있는 월은 전체 행의 22.87%지만 전체 오차의 4.33%였다. 보정출고가 곧 예측 대상 오염이라는 뜻은 아니다.
- 사용 가능한 재고보다 정상출고가 큰 기록을 포함한 월은 1,202건, 전체 오차의 0.94%였다. 상위 5% 오차 집단에서 이 표시의 비율은 0.93%, 나머지에서는 0.30%였다. 추가 점검 대상이지만 전체 오차를 설명할 규모는 아니다.
- 월별 집계에 보존된 재고 수지 불일치 표시는 평가 대상에서 0건이었다. 업무적 타당성까지 검증됐다는 뜻은 아니다.

위 조건은 서로 겹칠 수 있으므로 비율을 합산하면 안 된다. 표시가 없는 경우도 모든 데이터 오류가 없다고 단정하지 않는다.

## 원본 사례

기관과 품목의 실제 식별자는 공개 보고서에서 제외하고 사례 번호로 표시했다. 정확한 파일명과 헤더를 제외한 레코드 순번은 로컬 추출물에 남겼다. 여러 줄로 된 필드가 있을 수 있으므로 레코드 순번은 텍스트 파일의 물리적 줄 번호와 다르다.

### C01: 직전 월 0에서 사용 재개

예측 2,440.08, 실제 22,890이었다. 직전 월은 기록 1개에 정상출고 0이었지만 평가 대상 월은 16개 날짜에 양수 출고가 있었다. 가장 큰 날짜의 비중도 11.66%였다. 최근 3개월 평균은 8,600, 연속 과거 기록은 3개월이었다. 하루에 몰아 입력한 사례가 아니라 직전 월의 저활동과 이후 사용 재개가 함께 나타난 사례다. 왜 재개했는지는 이 기록만으로 확인할 수 없다.

### C02: 이미 높은 사용 규모를 낮게 예측

직전 월 실제 합계는 43,560, 최근 3개월 평균은 43,610이었다. 모델은 26,843.01을 예측했고 다음 달 실제는 45,980이었다. 직전 월은 20개 날짜, 다음 달은 22개 날짜에 양수 출고가 있었다. 다음 달 한 날짜의 최대 비중은 9.13%였다. 단순 평균이 이 사례에서는 더 가까웠다. 과거 사용 규모가 주어져 있었는데 모델이 크게 낮춰 예측한 사례이므로 사용 규모 보존·집단별 보정의 검증 근거가 된다. 손실함수나 규제가 원인이라고 이 사례만으로 확정하지 않는다.

### C03: 활동 날짜와 수량이 함께 증가

직전 월 양수 출고는 14개 날짜에 17,040이었다. 다음 달은 22개 날짜에 30,420이었고 예측은 12,153.89였다. 활동 날짜 수와 날짜당 수량의 변화가 월 합계에 가려질 수 있음을 보여준다. 단, 재고마감일은 실제 진료일이나 환자 방문일로 확인된 날짜가 아니므로 '출고가 기록된 날짜 수'라고 표현해야 한다.

큰 오차 20건과 비교 사례 7건 모두 평가 대상 월의 기록 날짜가 2개 이상이었다. 추출한 대상 월 기록에서 동일 내용 중복은 0건이었다. 원본 전체의 중복이 0건이라는 의미는 아니다. 또한 날짜가 분산됐어도 소급 입력 여부는 입력 시각이 없어 판별하지 못한다.

## 단위와 사용 규모를 나누어 본 결과

TABLET 분류는 기록 수량 합계의 약 75.05%, 전체 오차의 73.32%를 차지했다. 이 집단 자체의 WAPE는 34.62%로 전체보다 낮다. 따라서 정제만 유독 못 맞혀서 문제가 생긴 것이 아니라, 수량 비중이 커 전체 점수를 크게 좌우하는 것이다. EA 분류 WAPE는 31.97%지만 EA가 곧 주사기는 아니다. 주사기 성능은 별도의 품목 분류로 평가해야 한다.

단위 코드가 빈 행은 160,505건으로 전체의 약 44.67%였다. 이는 메타데이터 공백이지 단위 변환 오류가 확정된 것은 아니다. 정·개·병 등의 수량을 합친 WAPE는 동등한 임상 중요도나 비용 기준 점수가 아니다. 전체 지표는 유지하면서 단위·품목군별 지표를 함께 제시해야 한다.

예측 전에 알 수 있는 최근 3개월 평균 사용량으로 고정 구간을 나누었다. 서로 다른 단위의 숫자를 물리적으로 같은 사용량으로 해석하면 안 된다.

- 과거 평균 100 초과~1,000 이하: 102,657건, 전체 오차의 56.50%. 모델 WAPE 33.17%, 3개월 평균 38.90%.
- 과거 평균 1,000 초과~10,000 이하: 5,905건, 전체 오차의 18.41%. 모델 WAPE 31.15%, 3개월 평균 35.91%.
- 과거 평균 10,000 초과: 100건, 전체 오차의 2.49%. 모델 WAPE 25.89%, BIAS -18.47%. 3개월 평균은 WAPE 15.59%, BIAS +2.02%였다.

대량 사용 100건에서는 평균이 더 좋았지만, 이 집단만 평균으로 바꾸는 사후 계산상 개선 규모는 전체 WAPE 약 0.35%p 수준이다. 실제 전환 규칙을 적용하지 않았으며 검증 구간에서 재확인이 필요하다. 이 사례만으로 35%를 20%로 낮출 수 있다는 주장은 성립하지 않는다. 전체에서는 모델 35.43%, 3개월 평균 40.53%, 전월 값 그대로 사용 45.08%로 모델이 더 낫다.

## 다음 개선의 우선순위

1. 기존 원본에서 출고 기록 날짜 수, 양수 출고 날짜 수, 날짜당 양수 출고 평균·최대, 최근 7·14일 출고량, 월말 집중도를 월별로 복원한다. 예측 시점 이전 정보만 사용하고 전체 품목에 대해 생성해야 한다. 큰 오차 표본만 학습하지 않는다. 추출 사례에서 해당 날짜·수량 필드가 존재함을 확인했다.
2. 과거 사용 규모 대비 다음 달 변화량 또는 비율을 학습하는 방식과 집단별 편향 보정을 기존 모델과 비교한다. 규모를 나누는 기준과 보정값은 과거 검증 구간에서만 정한다. 정규화한 목표를 쓰면 손실함수의 가중치도 달라질 수 있으므로 원래 단위로 복원한 전체 WAPE를 비교해야 한다.
3. 전체 오차의 약 74.91%를 차지하는 과거 평균 100 초과~10,000 이하 구간에서 첫 번째 입력 정보가 도움이 되는지 우선 확인한다. 극단 사례만 고치는 실험에 치우치지 않는다.
4. 단위 공백의 원인과 품목군별 성능을 별도로 점검한다. 점수를 낮추기 위해 단위 불명 품목을 제외하거나 평가 집단을 축소하지 않는다.

신규 대규모 학습은 이번 점검에서 시작하지 않았다. 이미 실행 중인 후속 실험을 보존했다. 첫 단계 진단은 마쳤지만, 일별 정보 추가의 실제 WAPE 개선 폭은 아직 검증하지 않았다.

## 재현과 출처

- 집계 및 원본 점검 코드: [audit_target_records.py](../scripts/audit_target_records.py)
- 사용 규모별 점검 코드: [audit_volume_bias.py](../scripts/audit_volume_bias.py)
- 실제 처리 규칙: 원래 작업트리의 src/data_loader.py normalize_stock_chunk, aggregate_stock_chunk 및 src/features.py create_features. 이 브랜치의 기본 소스와 다를 수 있으므로 해당 실행 자료의 출처를 보존한다.
- 입력: 원래 작업트리 data/processed/stock_monthly.parquet, outputs/stock_feature_table.parquet, 첫 입력 변수 실험의 test_behavior_predictions.parquet, raw_stock/익스포트_*_수정.DAT 10개.
- 로컬 결과: outputs/target_record_audit_v2/aggregate.json, volume_bias.json, raw_case_summaries.json, scan_manifest.json, completed.json.
- 기관·품목 연결 키와 원본 발췌는 private_case_keys.json 및 private_raw_records.jsonl에만 저장했고 GitHub에 올리지 않는다.

재현 명령은 기존 실험의 Python 환경에서 `scripts/audit_target_records.py --source <원래 작업트리> --output <새 출력 경로>`를 실행한 뒤 `scripts/audit_volume_bias.py --source <원래 작업트리> --output <새 JSON 경로>`를 실행한다. 기존 출력은 덮어쓰지 않는다. 최초 실행에서 배열 형식 처리 오류를 수정했고, 빈 v1 폴더를 보존한 채 v2에서 전체 점검을 정상 완료했다.
