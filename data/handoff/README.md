## `censored_demand.parquet`

수요 **절단편향(censored demand)** 분석 산출물. ai#24 근거 데이터이며, ai#25 `demand_class` 판정의 입력으로 쓸 수 있다.

| 항목 | 값 |
|---|---|
| 행수 | **416,128** |
| 단위(grain) | **기관 × 부서 × 물품** |
| 원천 | `물품재고_정규화완료.parquet` (일별 원장 16,265,602행) |
| 기간 | 2024-01-01 ~ 2025-12-31 |
| 생성일 | 2026-07-18 |

### ⚠️ grain 주의
이 파일은 **기관×부서×물품**(416,128)이고, DB `inventory` 는 **기관×물품**(409,459)이다.
DB 에 맞추려면 부서를 합산해야 하며, **비율 컬럼은 재계산**해야 한다.

```python
s = df.groupby(["보건기관코드_en", "물품코드"], as_index=False).agg(
    재고0일=("재고0일", "sum"),
    T=("T", "max"),            # 기간이므로 sum 아님
    출고합=("출고합", "sum"),
)
s["재고0비율"] = (s["재고0일"] / s["T"]).clip(0, 1)   # ← 합산 후 재계산
```

## 컬럼 정의

| 컬럼 | 의미 |
|---|---|
| `보건기관코드_en` | 익명 기관코드 (원장 기준. DB `institution_id` 아님 — §매핑 참조) |
| `부서코드` | 부서 |
| `물품코드` | 물품코드 (DB `standard_code` 와 동일 체계) |
| `첫등장` | 해당 pair 가 원장에 처음 나타난 날 |
| `출고합` | 기간 내 `정상출고량` 합계 |
| **`재고0일`** | **마감재고 ≤ 0 이었던 일수** ★ |
| `관측일수` | 거래 기록이 존재한 일수의 합 |
| `T` | 관측 기간 = 첫등장 ~ 2025-12-31 (일) |
| **`재고0비율`** | `재고0일 / T` — **재고를 못 쥐고 있던 기간 비율** ★ |
| `재고보유일` | `T − 재고0일` |
| `mu_현재` | `출고합 / T` — 현재 방식(절단 무시) |
| `mu_보정` | `출고합 / 재고보유일` — 재고 있던 기간만으로 본 수요율 |
| `과소추정배수` | `mu_보정 / mu_현재`. **출고 0 인 190,032행은 NaN**(0 나눗셈) |

### ★ `재고0비율` 계산 방식 (중요)
원장은 **거래일에만 행이 있다.** 거래일 사이에는 직전 마감재고가 유지된다고 보고, 다음 거래일까지의 일수를 그 재고수준의 지속일로 처리해 누적했다.

```python
df["다음일"] = g["재고마감일"].shift(-1).fillna(END + pd.Timedelta(days=1))
df["지속일"] = (df["다음일"] - df["재고마감일"]).dt.days.clip(lower=0)
df["재고0일"] = np.where(df["마감재고량"] <= 0, df["지속일"], 0)
```

> **월 패널(`stock_monthly_panel.parquet`)의 `observed` 와 혼동 금지.**
> `observed=False` 는 "그 달에 거래행이 없어 0으로 복원한 달"이지 **재고가 없었다는 뜻이 아니다.**
> 두 지표의 상관은 0.473 에 불과하며, `observed` 기반으로 `재고0비율` 을 계산하면
> 절단 판정이 22.4% → 57.3% 로 과다해진다(오분류 62.8%).

## ⚠️ `mu_보정` 을 그대로 쓰면 안 되는 이유

`mu_보정 = 출고합 / 재고보유일` 은 **분모가 0 에 가까워지면 발산**한다.

- 예: `INH` — 재고0비율 100% → 재고보유일 1일 → `mu_보정` 16,335 (명백한 아티팩트)

이 컬럼은 **편향의 방향과 규모를 보여주는 진단값**이지 production 추정량이 아니다.
실제 보정에는 shrinkage 등 안정화가 필요하다(ai#26 의 Buhlmann 방식 참조).

## 기관코드 매핑

`보건기관코드_en`(예: `M3;34`)은 DB `institution_id`(예: `inst_0001`)와 **체계가 다르다.**
backend `import_ssis_dataset.py:222` 는 양쪽을 정렬해 `zip` 으로 매핑하는데, 이 방식은
**개수가 같을 때만** 유효하다.

```
원장 고유 기관코드 : 3,530
institutions       : 3,598      ← 68개 차이
```

길이가 다르면 `zip()` 이 조용히 잘라내므로, 매핑 전 **반드시 길이를 확인하고 다르면 중단**할 것.
이 매핑의 정확성 자체가 backend#16 으로 열려 있다.
